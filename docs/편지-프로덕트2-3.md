## 1. #2 (집필) — `02/` 계약

### 1-1. 파일명이 첫 번째 함정

```
02/m01-01.md  ~  02/m01-80.md          ← 이 이름이어야 한다
02/_index.json                          ← 있으면 좋다 (없어도 동작한다)
02/assets/…                             ← 도식 (SVG 권장, PNG·JPG 도 됨)
```

**`m` 접두어가 없으면 한 건도 읽히지 않는다.** `exam_meta.load_meta()` 가
`02/glob("m*.md")` 로만 훑기 때문이다. OCR 산출물 이름(`01-01.md`)을 그대로 두면
빌드가 이렇게 죽는다:

```
[error] 02/ 에서 문제를 못 읽었다: …\02
        파일명이 'mNN-NN.md' 여야 한다 (OCR 산출물 '01-01.md' 는 잡히지 않는다).
```

### 1-2. frontmatter — `id` 규칙은 기계가 검사한다

```yaml
---
id: m01-07                    # ★ 반드시 f"m{round:02d}-{question_no:02d}"
round: 1                      # 정수
round_label: 제1회 실전모의고사   # 화면에 그대로 노출된다 ('자사 ' 접두어는 빌드가 걷어낸다)
subject: 빅데이터 탐색           # 화면 과목 드롭다운 · 성적표 과목명
subject_no: 2                 # ★ 1..N 연속. 성적표·이론 링크의 축
question_no: 7                # 회차 내 1..N 연속
answer: ②
answer_index: 1               # ★ 0-based. answer 와 반드시 일치
difficulty: 중                 # 상 | 중 | 하
tags: [결측값, 이상값 처리]      # 성적표의 '취약 개념'이 이 태그로 만들어진다
derived_from: 01-10           # 기출 원문 id (없으면 생략)
has_figure: false
has_sql: false
has_table: false
verified: true
reviewed: false
needs_review: true            # 검수 큐 우선순위
---
```

`id` 가 규칙과 다르면 빌드가 파일명과 기대값을 찍고 멈춘다:

```
m01-07.md: id='m1-7' 가 규칙과 다르다 (기대 'm01-07')
```

**왜 이렇게 깐깐한가**: `id` 는 회차·문항 번호와 함께 **`pr_key`(`m01-1#7`)** 를 만들고,
그게 DB 임포트의 upsert 축(`UNIQUE (pd_id, pr_key)`)이다. 한 번 들어간 뒤에 바뀌면
같은 문제가 새 행으로 들어가고 `pr_id` 가 갈려서 **회원 오답노트와 정답률 집계가
조용히 끊긴다. 되돌릴 수 없다.**

`question_no` 는 회차 안에서 **1부터 빈칸 없이** 이어져야 한다.
번들(영상 편성 단위)이 `ceil(question_no / 10)` 로 계산되기 때문이다 —
80문항이면 `m01-1` ~ `m01-8` 8묶음이 된다.

### 1-3. 본문 — 섹션 4개, 순서 고정

```markdown
## 문제
다음 중 결측값 처리 방법으로 옳지 않은 것은?

## 지문
| 변수 | 결측 비율 |
| --- | --- |
| age | 3% |
| income | 42% |

```sql
SELECT * FROM t WHERE age IS NULL;
```

![결측 패턴](assets/m01-07-missing.svg)

## 보기
① 평균 대치
② 완전 제거
③ 다중 대치
④ 무작위 삽입

## 해설
42% 결측인 변수를 평균 대치하면 분산이 과소추정된다.
- ① 비율이 낮을 때만 쓴다
- ④ 근거 없는 값 생성이다
```

**`## 지문` 은 마크다운 그대로 두면 된다.** 화면(`check.js` 의 `mdb()`)이
표(`|`) · 펜스(```` ``` ````) · 불릿 · `![](assets/x.svg)` · `**굵게**` · `` `코드` `` 를 전부 렌더한다.
표를 따로 JSON 으로 쪼개거나 SQL 을 별도 필드로 빼지 **않는다** — 그러면 두 벌 렌더가 되어
같은 표가 두 번 나온다.

`## 지문` 이 없는 문제는 섹션을 아예 빼면 된다(빈 섹션도 괜찮다).

### 1-4. `## 보기` — 두 형태 모두 읽는다

```markdown
## 보기
① 평균 대치            ← 한 줄 형태
```

```markdown
## 보기
①

```sql
SELECT ... ;
```

②

```sql
SELECT ... ;
```
```

두 번째(표식만 있고 내용이 다음 줄) 형태도 지원한다 — SQLD 300문제 중 11건이 그 형태였다.
펜스는 버리고 코드 본문만 남긴다.

**번호 표식(`①` · `1.`)은 파서가 떼어낸다.** 화면이 번호를 다시 붙이므로
본문에 남기면 `① ① 평균 대치` 가 된다.

### 1-5. 검증 — 빌드가 먼저 죽는다

`--src 02` 빌드는 아래를 발견하면 **한 건이라도 있으면 멈춘다.** 목록으로 전부 찍는다.

| 검사 | 메시지 |
|---|---|
| `round`/`question_no` 가 정수가 아니다 | `round/question_no 가 정수가 아니다` |
| `id` 규칙 불일치 | `id=… 가 규칙과 다르다 (기대 …)` |
| `## 문제` 비었음 | `'## 문제' 가 비었다` |
| 보기 2개 미만 | `'## 보기' 를 N개만 읽었다` |
| `answer_index` 범위 밖 | `answer_index=… 가 보기 범위(0~N) 밖이다` |
| `subject`/`subject_no` 없음 | `subject/subject_no 가 없다 — 과목 필터·성적표가 죽는다` |

**조용히 통과시키지 않는 이유**: 깨진 문제가 DB 에 들어간 뒤에는 회원 채점 기록이
이미 붙어 있어서 지우는 것이 어려워진다.

## 2. #3 (요약노트) — `03/` 계약

### 2-1. 읽는 것은 `summary_*.html` 뿐이다

```
03/summary_planning.html      ← 1과목
03/summary_explore.html       ← 2과목
03/summary_modeling.html      ← 3과목
03/summary_interpret.html     ← 4과목
03/summary_index.html         ← 목차 (있으면 내용만 굽고 탭 목록에서는 뺀다)
03/assets/…                   ← 그림
```

- **`.md` 는 무시된다.** `build_theory()` 가 `03/glob("summary_*.html")` 만 훑는다.
  (SQLD 는 `.md` 와 `.html` 을 같이 두는데, 웹은 `.html` 만 쓴다)
- 파일명은 **ASCII 권장.** 한글이면 빌드가 `summary_ko1.html` 로 리네임해서 굽는다
  (동작은 하지만 어느 파일이 어느 과목인지 추적이 어려워진다)

### 2-2. `<h1>` 이 과목 번호를 정한다 — 여기가 핵심이다

```html
<h1>2과목 · 빅데이터 탐색</h1>
```

빌드가 정규식 `(\d+)\s*과목\s*[·:\-—\s]*(.*)` 로 읽어 `sub = 2` 를 뽑는다.

**그 숫자가 `02/` frontmatter 의 `subject_no` 와 같아야 한다.**
성적표가 "2과목 정답률 45% → 2과목 이론 보기" 로 잇는 유일한 연결이다.

패턴에 안 걸리면 `sub = 99` 로 목록 맨 뒤에 밀리고 탭 라벨이 파일명이 된다.
**에러가 나지 않는다** — 그래서 눈으로 확인해야 한다. 확인법은 §2-5.

`<h1>` 이 없으면 `<title>` 을 본다. 둘 다 없으면 99 다.

### 2-3. self-contained 1파일이어야 한다

빌드는 각 HTML 에서 **`<style>` 과 `<body>` 안쪽만** 뽑아 `theory_content.js` 에 굽고,
화면은 그걸 **shadow DOM** 에 넣는다.

| 하면 안 되는 것 | 왜 |
|---|---|
| `<link rel="stylesheet" href="…">` | `<head>` 가 버려진다 — 스타일이 통째로 사라진다 |
| `<script src="…">` · 인라인 `<script>` | shadow DOM 에 넣으면 실행되지 않는다 |
| 웹폰트 · CDN · `fetch()` | 외부 요청이 막혀 있다 |
| `body { … }` 셀렉터 | 빌드가 `:host` 로 바꾼다. 의도한 대로 안 걸릴 수 있다 |

→ **CSS 는 `<style>` 안에, 그림은 `03/assets/` 에 두고 상대경로로 참조**한다.
(빌드가 `assets/x.png` → `theory/assets/x.png` 로 고쳐준다)

인터랙션이 필요하면 CSS 만으로 되는 것(`<details>`, `:hover`, `:target`)을 쓴다.

### 2-4. 분량

SQLD 는 과목 2개에 `theory_content.js` 80KB 다. 빅분기 4과목이면 같은 밀도로 160KB 정도.
**이 파일은 문제집 화면이 처음 열릴 때 통째로 내려간다.** 과목당 40KB 를 넘기지 않는 게 좋다.
(카페24 트래픽 월 4,000MB 한도다)

## 3. 안 만들어도 되는 것

**`04/`(영상 대본) · `05/`(영상 번들) 은 이번에 필요 없다.**

빌드가 `05/` 가 없으면 `02/` 를 직접 읽도록 바뀌었다(`--src auto`). 영상 탭만 비고

나중에 영상을 붙일 때 번들 이름(`m01-1` … `m01-8`)이 지금 계산값과 같아서
`pr_key` 가 갈리지 않는다 — **문제를 다시 임포트할 필요가 없다.**

영상 매핑 파일은 품목별로 가른다: `data/youtube_map.bdae-w.json`.
(번들 이름이 품목 간에 겹쳐서 한 파일에 두면 SQLD 영상이 빅분기에 붙는다)

## 4. 한 장 요약

| | 규칙 | 어기면 |
|---|---|---|
| #2 | 파일명 `02/mNN-NN.md` | 한 건도 안 읽힌다 (빌드 에러) |

| #2 | `question_no` 회차 내 1..N 연속 | 번들·`pr_key` 가 어긋난다 |
| #2 | `subject_no` 1..N 연속 + `subject` 이름 | 과목 필터·성적표가 죽는다 (빌드 에러) |
| #2 | `answer_index` 0-based, 보기 범위 안 | 빌드 에러 |
| #2 | 지문은 마크다운 그대로 | 쪼개면 두 번 렌더된다 |
| #2 | 도식은 `02/assets/` (SVG 권장) | 그림이 사라진다 (경고만) |
| #3 | `03/summary_*.html` (`.md` 는 무시) | 이론 탭이 빈다 |
| #3 | `<h1>N과목 · 이름</h1>` | **에러 없이** 순서가 밀리고 라벨이 파일명이 된다 |
| #3 | 그 `N` = `subject_no` | 성적표의 학습 추천 링크가 끊긴다 |
| #3 | 외부 CSS/JS/폰트/fetch 금지 | 스타일이 사라지거나 동작하지 않는다 |
