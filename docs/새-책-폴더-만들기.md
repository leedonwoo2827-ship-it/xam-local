# 새 책 폴더 만들기 — OCR 한 것을 어디로 복사하는가

집필을 새로 시작할 때 폴더를 어떻게 만들고, 이미 OCR 해 둔 것을 어디에 넣는지.

---

## 1. 폴더 구조 — 무엇이 무엇인가

책 폴더 하나가 문제집 하나다. 실측(`D:\00work\ocr-output-260730`, 빅분기 9회차):

| 폴더 | 무엇 | 누가 만드는가 | 새 책에 복사? |
|---|---|---|---|
| `00/` | 원본 스캔 PDF (문제 3개 + 해설 3개) | 사람이 넣는다 | **복사한다** |
| `01/` | 기출 문항 MD 242개 (`01-01.md` …) | OCR 검수 화면 | **복사한다** ★ |
| `_rounds/` | 회차 원천 `m01.json` … (집필 산물) | **집필 화면** | 복사하지 않는다 |
| `02/` | 자사 문항 MD + `assets/*.svg` + `_index.json` | 파생(`build.py`) | 복사하지 않는다 |
| `03/` | 요약(이론) HTML 4개 — 과목당 1개 | 별도 단계 | 복사하지 않는다 |
| `04/` | `lesson_mNN.json` (영상 대본) | 파생(`build.py`) | 복사하지 않는다 |
| `05/` | 번들 72개 (`mNN-K/`) — 덱·이미지·대본 | 번들 단계 | 복사하지 않는다 |
| `06/` | 웹 산출물 (`check.html`, `problems.json` …) | 발행 빌드 | 복사하지 않는다 |
| `_book.json` | `{"pd": "...", "label": "..."}` | **손으로 만든다** | 새로 쓴다 |

**핵심은 하나다 — 복사하는 것은 `00/` 과 `01/` 뿐이다.** 나머지는 전부 파생물이라
앱이 다시 만든다. 파생물을 복사해 오면 새 책에 **옛 문항이 섞인 채로** 시작한다.

---

## 2. 순서

### ① 폴더를 만들고 원본·기출을 복사한다

새 폴더 이름은 자유다. 날짜를 앞에 두면 목록에서 정렬된다(`ocr-output-260730` 처럼).

```
D:\00work\새폴더이름\
```

그 안에 두 폴더만 복사한다:

```
D:\00work\ocr-output-260730\00\   →   D:\00work\새폴더이름\00\
D:\00work\ocr-output-260730\01\   →   D:\00work\새폴더이름\01\
```

> **★ `01/` 을 복사하는 이유** — 기출은 파생 근거다. 집필이 `derived_from` 에 기출
> id 를 적고, 모델이 `01/*.md` 를 실제로 **읽어서** 그 개념에서 문항을 만든다.
> `01/` 이 비어 있으면 집필은 돌지만 근거 없이 지어낸다.
>
> 새 과목(예: SQLD)이라면 `01/` 은 복사하지 않고 **OCR 검수 화면에서 새로 만든다** —
> `00/` 에 그 과목 PDF 를 넣고 `#/ocr` 로 간다.

### ② `_book.json` 을 만든다

폴더 루트에 이 파일을 만든다(메모장으로 만들면 **UTF-8** 로 저장할 것):

```json
{
  "pd": "bigdata",
  "label": "빅분기"
}
```

- `pd` — 웹(axexam)의 품목 코드. 웹의 `ex_product.pd_id` 와 **같아야 한다.**
  새 문제집이면 웹 관리자 `seed_pd.php` 에서 먼저 품목을 등록하고 그 코드를 쓴다.
- `label` — 화면에 뜨는 짧은 이름.

### ③ 앱에 연결한다

`run.bat` → `http://127.0.0.1:8870/` → 좌하단 **작업 폴더 버튼**(`빅데이터분석기사 ▲`)
→ **작업 폴더 추가** → 위에서 만든 경로를 넣는다. 이 목록은
`data/books.json` 에 남고, `active` 가 지금 보고 있는 책이다.

### ④ 집필한다

좌측 **문항 집필** → 회차 코드를 넣고(`m01`) → 과목을 체크 → **집필**.

- **1과목 = 1호출 = 20문항.** 4과목이면 4호출이다.
- 고른 과목을 **연달아** 돌린다. 사이를 벌리면 프롬프트 캐시가 풀려 비용이 4배가 된다.
- 실측: 과목 하나가 10~20분. 회차 하나(4과목)는 약 1시간.

집필 결과는 먼저 **스테이징**(`data/authoring/<회차>/`)에 들어간다. 검증을 통과한
것만 **반입** 버튼으로 `_rounds/` 에 들어가고, 그다음 **파생**이 `02/`·`04/` 를 만든다.

### ⑤ 그다음

`#/questions` 문항 교정 → `#/video` 번들·렌더 → `#/publish` 발행. 여기부터는 기존과 같다.

## 3. 집필자(SME) PC 에 처음 깔 때

| 무엇 | 어떻게 |
|---|---|
| 앱 | 저장소를 받고 `setup.bat` 1회 |
| Claude Code | 설치하고 **한 번 로그인** — 각자의 구독 계정으로 |
| 확인 | 앱의 `문항 집필` 화면 상단 **연결** 카드가 초록이면 된다 |

**API 키는 발급하지 않는다.** 집필은 그 PC 에 로그인된 Claude Code 구독으로 나간다 —
그래서 사용량과 한도가 사람별로 갈리고, 키가 유출될 자리도 없다.

> **★ `ANTHROPIC_API_KEY` 를 환경변수에 두지 말 것.** 앱은 자식 프로세스에서 그것을
> 빈 값으로 덮어 무력화하지만(`provider.scrubbed_env()`), 다른 도구는 그 키로 과금된다.
> 연결 카드가 켜져 있으면 경고를 띄운다.

> **★ 사내망(`lan.bat`)에서는 집필이 돌지 않는다.** 보기 전용 게이트가 POST 를 막는다.
> 남의 PC 브라우저로 내 구독을 태우는 일을 구조로 막은 것이다 — 집필은 늘 그 PC 에서 한다.
