# 수정 → 서버 동기화

무엇을 고치면 어디까지 다시 해야 하는가. **이 표가 전부다.**

경로는 슬래시로 쓴다(`02/assets`). 윈도우에서도 그대로 통하고, 문서를 스크립트로 다룰 때
역슬래시가 이스케이프로 먹히는 사고를 피한다.

| 고친 것 | 로컬에서 고치는 곳 | 빌드 | FTP | 관리자 임포트 |
|---|---|---|---|---|
| **요약노트 — 수정** | `03/summary_*.html` (`#/summary`) | 필요 | `theory*` 3~5개 · 41KB | **없음** |
| **요약노트 — 과목 추가/삭제** | `03/summary_<키>.html` 파일 자체 | 필요 | 같음 (+ 서버 옛 파일 손삭제) | 없음 |
| **문항 텍스트 — 수정** | `#/questions` | 필요 | **0개** | 붙여넣기 |
| **문항 — 추가/삭제** | **#2** (앱은 문항을 만들지 않는다) | 필요 | `figs/` 새 것 | 회차 단위 |
| **그림 — 추가** | **#2** 가 SVG 생성 → 앱이 파일로 씀 | 필요 | `figs/` 새 파일 | 붙여넣기 |
| **그림 — 수정** | 같음 | 필요 | `figs/` 그 파일 | 없음 |
| **영상 링크** | `#/publish` ② | 필요 | `videos.private.json` **1개** | 없음 |
| **영상 내용** | `#/questions` → `#/video` 재렌더 | 필요 | 위와 같음 | 붙여넣기 |
| **코드(PHP)** | `axexam/web/...` | 없음 | 바뀐 것만 | 없음 |
| **회차 추가** | **#2** 로 생성 | 필요 | `theory*` · `figs/` 새 것 | 회차 전체 |

**요약노트는 FTP 만, 문항 텍스트는 붙여넣기만.** 서로 겹치지 않는다.

> ★ **SVG 는 #2(클로드 데스크탑)에게 시킨다.** 앱에는 그림을 그리는 기능이 없다 —
> `_rounds` 의 인라인 SVG 를 파일로 쓰고, 화면에서 지우거나 스캔에서 크롭해 붙이는
> 정도만 한다. 다른 도구로 만든 SVG 를 쓰려면 #2 에 넘겨 `_rounds` 에 넣게 한다.

## ① 요약노트 고치기

```
#/summary  →  과목 고르기  →  편집  →  [저장]
```

**`.html` 파일 자체를 고친다.** 편집창에 HTML 원문이 그대로 뜬다(마크다운이 아니다).
저장 전에 `.bak` 을 만들고 원자적으로 쓴다.

> **왜 `.html` 인가** — 발행되는 것이 `.html` 이다(빌더 `build_theory()` 가
> `summary_*.html` 만 읽는다). 예전에는 `.md` 를 고치고 `.html` 은 #2 가 다시 만드는
> 구조여서 **두 파일이 갈렸다.** `.html` 을 직접 고치면 고친 것이 그대로 발행된다.
> `.md` 가 있는 폴더에서는 `.md` 를 고친다 — 화면 라벨이 어느 파일인지 알려 준다.

```
#/publish  →  ③ [빌드 실행]  →  ⑤ [업로드 폴더 만들기]  →  FileZilla
```
바뀌는 것은 `pd/bigdata/theory.js` · `theory_content.js` · `theory/*.html` 뿐이다.
**임포트는 필요 없다** — DB 가 아니라 정적 파일이다.

### 과목이 늘거나 이름이 바뀔 때

파일 이름이 곧 과목 키다. 앱은 **폴더를 세어** 목록을 만든다(`paths.summary_keys()`) —
코드에 과목을 하드코딩하지 않는다. `03/summary_<키>.html` 을 넣으면 생기고 지우면 없어진다.

지금 4과목:
```
summary_planning.html    빅데이터 분석 기획
summary_explore.html     빅데이터 탐색
summary_modeling.html    빅데이터 모델링
summary_interpret.html   빅데이터 결과 해석
```

★ **`<h1>N과목 · 이름</h1>` 의 이름은 `_rounds` 의 `subject` 와 글자까지 같아야 한다.**
다르면 성적표에서 그 과목으로 가는 링크가 붙지 않는다.

지운 뒤에는 **서버의 옛 파일이 남는다** — FTP 는 지우지 않는다. 목록(`theory.js`)에서
빠지니 화면에는 안 보이지만 URL 을 아는 사람은 볼 수 있다. 손으로 지운다.
과목이 늘면 게시판 말머리도 다시 맞춘다(`/adm/exam_board_sync.php`).

## ② 문항 텍스트 고치기

```
#/questions  →  고침  →  저장
```
앱이 세 파일을 함께 쓴다 — `_rounds/mNN.json` · `02/mNN-QQ.md` ·
`05/mNN-K/source/lesson_mNN.json`. **손으로 하나만 고치면 갈려서 저장이 막힌다.**

```
#/publish  →  ③ [빌드 실행]
           →  ④ 부분 임포트  →  회차/번들/문항 고르기  →  [부분 파일 만들기]
           →  그 내용 복사
/adm/exam_import.php  →  '또는 붙여넣기' 에 붙여넣고  [임포트 실행]
```

기대 리포트: **갱신 N · skip_edited 0**

| 고른 단위 | 크기 |
|---|---|
| 문항 하나 | 2.6KB |
| 번들 하나 (10문항 · 영상 1편) | 13KB |
| 회차 하나 (80문항) | 92KB |
| 전체 (720문항) | 714KB |

**FTP 는 0개다.** 그림이 바뀌지 않았으면 올릴 파일이 없다.

> 임포트가 **DELETE 를 하지 않아서**(`adm/exam_lib/problem.php:13`) 부분 파일이 안전하다 —
> JSON 에 없는 문항은 서버에 그대로 남는다.
> 이득은 용량이 아니라 **확인**이다. 전체를 올리면 `갱신 1 · 변경없음 719` 로 나와서 내가
> 고친 것이 들어갔는지 알기 어렵다. 문항 하나면 `갱신 1` 만 찍힌다.

### 경고 `skip_edited` 가 0 이 아니면

그 문항을 **전에 웹에서 고친 적이 있다.** `edited_by` 가 차 있으면 재임포트가 그 행을
건너뛴다(웹 수정을 지키기 위한 것). **로컬 수정이 안 들어간다.**

```
/adm/exam_problem_form.php?pr_key=m04-2#12   →  [원본 복원]  →  다시 임포트
```

## ③ 그림 (SVG)

**만드는 것은 #2 다.** 앱은 `_rounds` 의 인라인 SVG 를 파일로 쓴다.

```
_rounds/mNN.json 의 assets[] (인라인 SVG)     ← #2 가 만든다
        ↓ 앱이 저장할 때 파일로 씀
02/assets/m04-12-roc.svg
        ↓ 빌드가 '쓰이는 것만' 모아 복사
06/pd/bigdata/figs/m04-12-roc.svg
        ↓ FTP
/www/exam/pd/bigdata/figs/m04-12-roc.svg
```

빌더는 `02/assets` · `04/assets` · `03/assets` · `02/images` · `01/images` 를 훑는다.
지금 `02/assets` 246개 중 245개가 복사된다 — 1개는 아무 문항도 참조하지 않는 고아이고
사전점검이 `쓰이지 않는 SVG` 로 알려 준다.

**추가** — 새 파일이라 캐시 문제가 없다. `figures_json` 이 바뀌므로 **임포트도 필요하다.**

**수정**(같은 이름) — 빌드 → 그 파일만 FTP. 임포트는 필요 없다.

> **캐시** — 그림 캐시를 **7일에서 1시간으로 줄였다**(`exam/.htaccess`, 2026-08-04).
> 예전에는 같은 이름으로 덮어쓰면 이미 본 사람에게 최대 7일간 옛 그림이 보였다. 서버에는
> 새 파일이 있으니 "안 올라갔나?" 하고 다시 올려도 안 바뀌어 원인을 찾기 어려웠다.
> 245개가 199KB 뿐이라 1시간으로도 비용이 사실상 없다.
>
> **그래서 바꿀 때는 다른 이름을 권한다.** 1시간이라도 수업 직전에는 길다. 새 이름은
> 새 URL 이라 캐시가 아예 없다. 이름은 `_rounds` 의 `assets[].name` 이므로
> **#2 에 "새 이름으로 만들어 달라" 고 요청한다.**
> 내 화면에서 즉시 확인하려면 `Ctrl+Shift+R`.

### 지금 이름이 무엇인지 보는 곳

바꾸려면 현재 이름을 알아야 한다. 두 곳에서 보인다.

| 어디 | 무엇이 보이나 |
|---|---|
| 앱 `#/questions` | 그림 바로 아래에 `assets/m04-12-roc.svg` |
| 관리자 `/adm/exam_problem_form.php` | **그림** 표에 파일명 + 서버 경로 (2026-08-04 추가) |

관리자 화면에는 원래 없었다 — 캐시 때문에 이름을 바꿔야 하는데 이름을 볼 곳이 없으면
아무 의미가 없어서 넣었다. `pr_key`(예: `m04-2#12`)로 열면 그 문항의 그림 목록이 나온다.

**삭제** — `02/assets` 에서 없어지고 다음 빌드의 `figs/` 에도 안 들어간다. 그런데
**FTP 는 서버의 옛 파일을 지우지 않는다.** 오류·저작권 때문에 지웠다면
`/www/exam/pd/bigdata/figs/` 에서 손으로 지운다.

## ④ 문항 추가 · 삭제

**앱은 문항을 만들거나 지우지 않는다.** `#/questions` 는 있는 문항을 고치는 화면이다
(`store.py` 에 `save`·`set_review`·`reindex` 만 있다). 문항을 늘리거나 줄이는 것은
**#2 의 일**이고 회차 단위로 다시 만든다.

### 경고 문항을 지우면 서버에서는 안 없어진다

임포트가 DELETE 를 하지 않으므로, 로컬에서 문항을 빼고 다시 임포트해도 그 행은 DB 에
남아 화면에 계속 나온다.

```
/adm/exam_problem_list.php  →  그 문항의 [숨기기]     ← pr_open = 0
```
이게 정식 경로다. 오류 신고를 받은 직후 가장 먼저 하는 동작이기도 하다 — 고치는 것보다
먼저 이용자 화면에서 빼는 편이 낫다.

## ⑤ 영상

### 링크만 바꿀 때 — 가장 싸다

```
#/publish ②  →  링크 수정 (또는 [링크 붙여넣기])
          ③  →  [빌드 실행]
          ⑤  →  pd/bigdata/videos.private.json  1개만 FTP
```
`api/videos.php` 가 그 JSON 을 **요청마다 다시 읽는다**(캐시·DB 없음). 임포트도 관리자
화면도 필요 없다.

★ 드라이브·유튜브에서 **파일을 지우고 다시 올리면 ID 가 바뀐다.** 내리지 말고 드라이브의
**버전 관리**로 덮어쓰면 ID 가 유지되어 매핑을 고칠 필요가 없다.

### 내용이 바뀔 때 — 앱이 대상을 잡아준다

문항을 고치면 `05/lesson` 이 갱신되고 그 번들의 mp4 가 낡는다.
`services/render/bundles.py` 가 `mp4 mtime < lesson mtime` 을 보고 **`재렌더`** 로 표시한다.

```
#/video  →  '재렌더 N'  →  [미완성만 렌더]          ← 그 번들만
       →  드라이브에서 그 mp4 만 버전 관리로 덮어쓰기 (ID 유지)
       →  videos.private.json 1개 FTP
```
재렌더 단위는 **번들(10문항)** 이다. 1문항을 고쳐도 그 1편만 다시 만든다.

```
왼쪽(로컬)    D:/00work/ocr-output-260730/_upload
오른쪽(서버)  /www/
```
`_upload` 안이 **이미 서버와 같은 모양**이다(`exam/` `adm/` `theme/` `extend/`
`index.php` `.htaccess`). 통째로 끌어놓으면 끝이고, 다 올리면 `[다 올렸습니다 — 지우기]`.

**바뀐 것만 올리려면** 덮어쓰기 대화상자에서 `크기·시간이 다른 것만` 을 고른다.

설정(한 번만): 전송 유형 **바이너리** · 동시 전송 **2** · 문자셋 **UTF-8 강제**

## 절대 하지 말 것

- **서버 파일을 직접 고치기** — 다음 빌드가 덮어쓴다. 원천을 고친다.
- **`_rounds` · `02/*.md` · `05/lesson` 을 손으로 고치기** — 셋이 갈리면 저장이 막힌다.
- **`--book` / `--pd` 생략** — 둘 다 기본값이 SQLD 라서 **라이브 SQLD 를 덮어쓴다.**
- **영상 파일을 지우고 다시 올리기** — ID 가 바뀐다. 버전 관리로 덮어쓴다.
- **그림을 같은 이름으로 덮어쓰고 "안 올라갔다" 고 판단하기** — 캐시(1시간)다.
  급하면 #2 에 새 이름으로 만들어 달라고 한다.
- **문항을 로컬에서 지우고 서버도 지워졌다고 생각하기** — 임포트는 DELETE 를 하지 않는다.
  `[숨기기]` 를 쓴다.
- **웹에서 고치고 로컬 반영을 미루기** — `edited_by` 가 차 있는 동안 로컬 수정이 안
  들어가고, 어느 쪽이 최신인지 잃는다.
