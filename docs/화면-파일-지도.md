# ★ 정답이 바뀔 때 — 반드시 함께 확인할 것

정답만 바꾸면 되는 게 아니다. **네 곳이 연동된다.**

## ① 낭독문 접두어 — 앱이 자동으로 고친다

`services\book\store.py` 가 `answer_index` 변경을 감지해 낭독문의
`"정답은 N 번입니다."` 를 새 번호로 고친다. 그리고 이렇게 알린다:

> 정답이 바뀌어 낭독문 접두어를 고쳤습니다. **본문은 그대로입니다 — 내용도 정답에 맞는지
> 확인하세요.**

**접두어만 고칩니다.** 해설 본문이 "①번이 정답인 이유는…" 이라고 설명하고 있으면 그건
사람이 고쳐야 한다. 안 고치면 **음성이 새 번호를 읽고 내용은 옛 번호를 설명한다.**

## ② 영상 재렌더 — 앱이 대상을 잡아준다

낭독문이 바뀌었으므로 음성을 다시 만들어야 한다.
`services\render\bundles.py` 가 `mp4 < lesson` 을 감지해 그 번들을 `재렌더` 로 표시한다.

```
#/video → '재렌더 1' → [미완성만 렌더] → 그 번들만 다시 만듦
→ 드라이브에서 그 mp4 만 교체(버전 관리로 덮어쓰면 ID 유지)
→ 매핑은 그대로. videos.private.json 만 FTP
```

## ③ 임포트 — `pr_hash` 가 바뀌어 '갱신' 으로 잡힌다

부분 파일로 올리면 확인이 쉽다:

```
앱에서 그 문항만 잘라낸 파일 → /adm/exam_import.php
기대: 신규 0 · 갱신 1 · 변경없음 0
```

## ④ ⚠ 웹에서 고친 문제는 임포트가 **건너뛴다**

`adm\exam_lib\problem.php:18~20` 의 규칙이다:

> `edited_by` 가 비어 있지 않은 행은 건드리지 않는다. 관리자가 웹에서 고친 문제다.
> 재임포트가 이걸 덮으면 수정이 사라진다. 되돌리려면 화면에서 **"원본 복원"**
> (`edited_by` 비우기)을 명시적으로 눌러야 한다.

**즉 그 문항을 전에 웹에서 고친 적이 있으면, 로컬에서 정답을 바꿔 임포트해도 안 들어간다.**
리포트에 `skip_edited` 로 집계된다 — **0 인지 확인할 것.**

들어가게 하려면 관리자 화면에서 그 문항의 **"원본 복원"** 을 눌러 `edited_by` 를 비운 뒤
다시 임포트한다 (`ex_problem_unlock()`).

> 그 대가도 적혀 있다: 웹 수정본은 `02/` 원본과 어긋난 채로 남는다. 주기적으로 `02/` 로
> 역반영하지 않으면 언젠가 "원본 복원" 이 낡은 내용을 되살린다.
> **그래서 이 프로젝트의 규칙은 "문항은 로컬에서만 고친다" 다.**

## 정답 변경 체크리스트

```
□ #/questions 에서 정답 변경
□ 앱이 낭독문 접두어를 고쳤다는 안내를 읽음
□ 해설 본문이 새 정답을 설명하는지 눈으로 확인      ← 자동 아님
□ #/video 에 '재렌더 1' → 렌더
□ 드라이브 mp4 교체 (버전 관리 = ID 유지)
□ 빌드 → 그 문항만 부분 JSON
□ 임포트: 갱신 1 · skip_edited 0            ← 0 아니면 '원본 복원' 먼저
□ videos.private.json FTP
□ 웹에서 그 문항 열어 정답·해설·영상 확인
```
