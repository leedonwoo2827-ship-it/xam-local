### ⚠ 조심할 것 셋

**① `pr_key` 안정성이 전부다 — 이게 유일한 진짜 위험이다**

파이프라인은 `m01-1#7` 을 기계가 만든다. 엑셀에서 사람이 손으로 넣으면
**오타 하나에 같은 문제가 새 행으로 들어가고 `pr_id` 가 갈린다.**
`ex_attempt_item` / `ex_wrong` 이 `pr_id` 를 참조하므로 회원 오답노트와
정답률 집계가 조용히 끊긴다. **되돌릴 수 없다.**

→ **"엑셀 업로드"가 아니라 "엑셀 왕복(export → edit → import)"으로 설계한다.**
   - 내보내기에 `pr_key` 를 **첫 열**로 박는다 (읽기 전용으로 안내)
   - 기존 문제는 그 `pr_key` 로 매칭한다
   - 신규만 `pr_key` 빈칸 → 서버가 규칙대로 생성 (`{pd_id}{rd:02d}-{part}#{no}` 같은 결정적 규칙)
   - 임포트 전에 **드라이런**(무엇이 신규/갱신/건너뜀인지만 보여주고 쓰지 않음)을 넣는다

**② PHPExcel 은 폐기된 라이브러리다.** 후속은 PhpSpreadsheet.
그누보드가 아직 품고 있지만 **PHP 8.4 에서 실제로 도는지 서버에서 확인해야 한다.**

**③ 진실 원천이 셋이 된다.** 지금은 `02/` → DB, 웹편집 → `edited_by` 보호.
엑셀이 붙으면 경로가 하나 더 늘어난다. **`edited_by` 보호 규칙을 엑셀 임포트에도 똑같이 적용**하고,
엑셀로 들어온 문제는 `02/` 에 원본이 없다는 것을 어딘가에 표시해야 한다
(`src_id` 를 비우거나 `src_from='xlsx'` 같은 표식).

### 더 싼 대안 — CSV

`fgetcsv()` 가 PHP 내장이라 라이브러리가 0이다. **90% 의 가치를 10% 의 비용으로.**
한글은 내보낼 때 UTF-8 BOM(`\xEF\xBB\xBF`)을 붙이면 엑셀이 제대로 연다.
읽을 때는 CP949 로 저장된 파일에 대비해 `mb_detect_encoding` → `mb_convert_encoding`.

단점: 지문·해설에 줄바꿈과 쉼표가 많아 셀 안에서 깨져 보인다. 편집 경험은 xlsx 가 낫다.

→ **먼저 CSV 왕복으로 만들고, 편집 불편이 실제로 문제가 되면 xlsx 로 올린다.**
