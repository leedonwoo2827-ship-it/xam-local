# 질문 답변 운영 — 아침에 하는 일

과목게시판에 들어온 질문에 LLM 초안을 붙여 검수하고, 승인하면 게시판에 답변 댓글이
자동으로 달린다. **이 문서만 읽고 할 수 있어야 한다.**

---

## 한 장 요약

```
회원   문제 풀다 막힘 → [질문하기] → 과목게시판 글쓰기
                                        ↓
운영자 /adm/exam_qna_list.php  「질문 검수」
       ① [가져오기]                 게시판 글 → 검수 큐
       ② 체크 → [선택 초안 요청]     LLM 초안 (건수·원가 확인창)
       ③ [답변] → [초안을 답변란으로 복사] → 고쳐서 [승인 · 공개]
                                        ↓
       게시판 원글에 [관리자 답변] 댓글 + 초록 [답변완료] 배지
```

**초안은 이용자에게 절대 보이지 않는다.** 회원 API 는 `qa_answer` 만 읽고 `qa_draft` 는
SELECT 목록에 없다 — 검수 없이 공개되는 경로가 구조적으로 존재하지 않는다.

---

## ① 가져오기

`/adm/exam_qna_list.php` 맨 위 `게시판에서 가져오기`.

- 문제집을 고르거나 `열린 문제집 전부`
- 버튼 옆에 **아직 안 가져온 건수**가 나온다. `가져올 새 글이 없습니다` 면 누를 필요 없다
- 같은 글을 두 번 가져오지 않는다 (`bo_table` + `wr_id` 로 판정)

### 왜 이 단계가 필요한가

질문은 **그누보드 과목게시판**으로 들어오고, 초안·검수·승인은 **`ex_qna` 테이블** 위에
있다. 두 세계를 잇는 것이 이 버튼이다. 이게 없던 동안 초안 기능은 다 만들어져 있었는데도
큐가 영원히 비어 있었다.

### 문항 자동 연결 — 초안 품질의 핵심

제목의 `1회 61번` 같은 표식을 읽어 그 문항을 찾아 붙인다. 붙으면 **발문·보기·정답·해설이
프롬프트에 들어가서 모델이 문제를 풀지 않고 설명만 한다** — 환각이 구조적으로 줄어든다.

| 제목 | 연결 |
|---|---|
| `[1회 61번] 정밀도 재현율 분모를…` | `m01-7#61` ✔ |
| `1과목 공부 순서 추천 부탁드립니다` | 없음 → 과목 정보만으로 초안 (품질이 떨어진다) |

`m01-7#61` 처럼 `pr_key` 를 직접 적어도 잡는다.

→ **회원에게 "제목에 회차와 번호를 적어 주세요" 를 안내하면 답변 품질이 올라간다.**
   문제풀이 화면의 `[질문하기]` 안내 문구에 넣을 만한 것이다.

### 오류 신고 자동 분류

제목에 `오류 · 신고 · 틀린 · 잘못` 이 있으면 <kbd>오류 신고</kbd> 로 분류한다.
오류 신고는 질문권을 쓰지 않고 검수 우선순위도 다르다.

## ② 초안 일괄 요청

표 머리의 체크박스로 전체 선택 → `[선택 초안 요청]`.

```
5건에 LLM 초안을 만듭니다.
예상 원가 최대 3.00원 × 5건
```

**확인창이 건수와 돈을 말한다.** "진행할까요?" 만 묻는 창은 정보가 없어서 습관적으로
확인을 누르게 되고, 그때 원가가 나간다.

### 체크할 수 있는 것

`대기` · `검수 대기` 만이다. `완료` · `반려` 는 체크박스가 없다 — 눌러도 안 되는 것을
체크하게 두면 실패 목록만 길어진다.

### 누르면 이 화면이 뜬다 — 닫지 않는다

```
┌────────────────────────────────────────────────┐
│            초안 만드는 중 · 5건                  │
│                                                │
│                   14초                          │
│                                                │
│   ███░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░       │
│                                                │
│   최대 약 190초 걸립니다.                        │
│   이 창을 닫거나 새로고침하지 마십시오.            │
│   중간에 끊기면 그 질문이 '초안 생성 중' 에         │
│   갇힙니다 (그때는 아래 [멈춘 초안 풀기] 로 되돌림) │
│   시간이 부족하면 일부만 처리하고 남은 건수를        │
│   알려 드립니다.                                 │
└────────────────────────────────────────────────┘
```

- **경과 초**가 1초마다 올라간다. 진행 바는 최대 예상 시간 기준이다
- **버튼이 잠긴다** — 두 번 누르면 원가가 두 번 나간다
- 화면 뒤로 목록이 그대로 보인다. 어느 5건을 돌리는 중인지 확인할 수 있다

★ **실시간 진행률(3/5 건)은 줄 수 없다.** 서버가 한 요청 안에서 도는 중이라 중간에
  보고할 통로가 없다. 그래서 "몇 번째" 대신 **"언제까지 기다리나"** 에 답한다.
  그것만으로 새로고침·재클릭을 막는 것이 목적이다.

★ **최대 시간의 근거**: 예산 100초 + LLM 타임아웃 90초 = 190초. 예산 검사를 통과한
  직후 시작한 1건이 타임아웃까지 갈 수 있어서 그만큼을 더한다.
  두 값은 `EX_DRAFT_TIMEOUT`(prompt.php)과 `$DRAFT_BUDGET`(exam_qna_list.php) 이고,
  화면이 그 상수를 읽어 표시한다 — 숫자를 두 곳에 적으면 안내와 실제가 갈린다.

### 시간이 부족하면 일부만 처리한다

**100초 예산**으로 끊고 남은 건수를 알려 준다. 다시 체크해서 누르면 이어진다.

> `초안 3건 생성 · 원가 4.2100원 · 2건은 시간이 부족해 남겼습니다`

조용히 끊기지 않게 하려는 것이다. 예산 없이 돌리면 PHP 실행시간 제한이 먼저 죽고
**어디까지 처리됐는지 모른 채** 화면이 끊긴다.

### 중간에 끊겼으면 — [멈춘 초안 풀기]

브라우저를 닫거나 PHP 가 죽으면 그 질문이 `초안 생성 중` 에 남는다. **그 상태는 다시
집히지 않아서 질문이 큐에서 조용히 사라진다** — 가장 찾기 어려운 종류의 고장이다.

`초안 생성 중` 이 있으면 [가져오기] 카드 아래에 버튼이 나타난다. 지금 돌고 있는 것이면
곧 사라지고, **10분이 지나도 남아 있으면** 끊긴 것이니 그 버튼으로 되돌린다.
초안이 이미 있으면 `검수 대기` 로 되돌아간다 — 원가를 다시 쓰지 않는다.

### 원가·모델 설정

`/adm/exam_llm.php` 「답변 초안 설정」

| 칸 | 뜻 |
|---|---|
| API 키 | `/data/exam_secret.php` 에 저장. 웹 조회 403 · git 유입 차단 · 마스킹만 표시 |
| 연결 테스트 | 키·모델명·한글 생성·토큰 기록을 미리 확인 |
| 차감(원) | **회원에게서 빼는 것.** 질문 1건 = 10원 |
| 원가 상한(원) | **우리가 LLM 에 내는 것의 경고선.** 넘으면 `원가 상한 초과` 표시 |

모델이 막히거나 값이 오르면 `ex_product` 한 행만 바꾼다 — PHP 를 고치지 않는다.
`provider` 를 `anthropic` 으로 적으면 엔드포인트·헤더가 자동으로 갈린다.

### 원가는 건당이다 — 묶어도 안 줄어든다

문항마다 발문·보기·해설이 달라서 **질문 1건 = LLM 호출 1건**이다. 일괄이 줄여주는 것은
클릭 수이고 돈이 아니다.

| 건수 | 실측 기준 |
|---|---|
| 1건 | 약 0.8~1.6원 |
| 10건 | 8~16원 |
| 100건 | 80~160원 |

회원에게서 받는 것은 질문 1건 **10원**(`cost_units`)이다. 마진은 충분하다.
시스템 프롬프트는 문항마다 같아서 **프롬프트 캐시가 붙는다** — 초안 화면의
`토큰 in / cache / out` 중 `cache` 가 그것이고 이미 싸게 계산된다.

### ★ 실패해도 돈은 나간다

응답이 왔고 출력 토큰을 썼는데 본문만 비었으면, 공급자는 그것을 청구한다.
그래서 실패분 원가를 **따로 합산해 보여준다**:

> `초안 4건 생성 · 원가 3.2297원 · 실패 1건 (실패분에도 0.9412원이 나갔습니다)`

`ex_log` 에도 `fail:<qa_id>` 로 남는다. 그 표가 "누가 언제 얼마를 썼는가" 의 유일한
근거인데, 실패를 빼면 그 근거가 실제 청구보다 낮아진다.

### 2026-08-04 실측 — max_tokens 를 1200 → 2400 으로 올린 이유

5건을 돌렸더니 3건이 빈 응답으로 실패했다. 옛 안내는 "모델명을 확인하십시오" 였는데,
**같은 모델로 2건은 성공했으니** 모델명 문제가 아니었다. 진단을 붙여 보니:

```
finish_reason=length · 출력 토큰 1200 (= max_tokens) · 사고과정 1832자
```

`deepseek-v4-flash` 는 **추론형 모델**이다. 1200 토큰을 사고 과정에 전부 쓰고 본문에
쓸 것이 남지 않았다. 성공한 2건은 그 문항의 사고가 짧았을 뿐이다.

★ **사고 과정은 답이 아니라 사고다.** 그걸 답변으로 쓰지 않는다 — 상한을 올려 본문이
  나올 자리를 만드는 것이 옳은 해결이다. 프롬프트 규칙 9("정답·해설이 이미 주어졌으므로
  다시 풀지 않는다")로 사고 자체도 줄인다.

같은 증상이 또 나오면 화면이 그 한 줄을 찍어 준다. 그때 `EX_DRAFT_MAX_TOKENS`
(`adm/exam_lib/prompt.php`)를 올린다.

## ③ 검수 · 승인

행의 `[답변]` → `/adm/exam_qna_form.php`

1. **LLM 초안** 을 읽는다 (파란 박스, 이용자에게 안 보임)
2. `[초안을 답변란으로 복사]`
3. 고친다 — 질문자가 고른 보기가 왜 아닌지까지 짚으면 재질문이 줄어든다
4. `공개` 체크 확인 (개인 사정이 섞인 질문은 체크를 푼다)
5. `[승인 · 공개]`

승인하면:

- `qa_answer` 가 확정되어 이용자에게 공개
- **게시판 원글에 `[관리자 답변]` 댓글이 달린다**
- 게시판 배지가 주황 `답변 준비 중` → 초록 `답변완료`

### 게시판에도 답을 다는 이유

질문자는 게시판에 글을 썼고 목록·알림을 거기서 본다. 우리 DB 에만 답이 들어가면
**그 사람 입장에서는 아무 일도 일어나지 않은 것**이다. (게시판 배지는 `ex_qna` 를 보므로
켜지는데 정작 글을 열면 댓글이 없다 — 그게 더 나쁘다.)

### 오타를 고쳐 다시 승인하면

**그 댓글이 갱신된다.** 새로 달지 않는다. `ex_qna.qa_reply_wr_id` 가 우리가 쓴 댓글의
`wr_id` 를 들고 있어서 가능하다.

### 단건 초안

질문 아래 `[초안 생성]` — 일괄과 같은 함수를 쓴다. 버튼 옆에 **문항이 연결됐는지**가
적혀 있다. 만든 뒤에 알면 원가를 이미 쓴 뒤다.

### 반려

답할 수 없으면 사유를 적고 `[반려 · 환불]`. `cost_units` 만큼 환불된다 —
답을 못 하는데 포인트를 가져가면 민원이 된다. 사유는 **이용자에게 그대로 보인다.**

## 지금 무료다 — 유료화 스위치

게시판으로 들어온 질문은 **차감하지 않는다** (`cost_units = 0`). 게시판 글쓰기는
그누보드가 처리해서 우리 코드를 지나지 않기 때문이다. 걷지 못한 돈을 걷은 것처럼
기록하면 회계가 틀어진다.

유료화는 **회원 폼 경로**(`exam/api/qna.php`)를 붙이는 일이고, 스위치는 이미 있다:

```php
// exam/api/qna.php
$charge = !empty($cfg['charge']) && $kind !== 'report';
```

`ex_product.pd_config` 에 `{"charge":1}` 을 넣으면 차감한다. 오류 신고는 `charge` 를
켜도 **항상 무료**다 — 오류 제보에 돈을 받으면 아무도 안 알려준다.

## 배지 — 게시판에서 보이게 하려면

`답변완료` / `답변 준비 중` 배지는 **복사한 스킨**에서 나온다. 설정은
[게시판-스킨.md](게시판-스킨.md) 를 본다. 요약:

| | |
|---|---|
| 스킨 | `basic-xam` (basic 복사본). 게시판 관리 → 스킨 |
| 도우미 | `/www/exam/lib/qna_badge.php` |
| 판정 | `ex_qna.qa_status = 'approved'` — 게시판 댓글 수로 보지 않는다 |

★ **`모바일 스킨` 은 따로다.** `bo_mobile_skin` 을 안 바꾸면 휴대폰에서 배지가 안 보인다.

## 안 될 때

| 증상 | 원인 |
|---|---|
| 게시판에 배지가 하나도 없다 | **`[가져오기]` 를 안 했다.** 배지는 `ex_qna` 에 그 글이 있어야 뜬다 |
| 검수 큐가 0건이다 | 같은 이유. 게시판에 글이 있어도 가져오지 않으면 큐는 빈다 |
| `과목게시판이 없습니다 — bo_table = …` | 그 이름 그대로 게시판을 만들어야 한다 → [게시판-만들기.md](게시판-만들기.md) |
| 배지가 여전히 없다 (가져온 뒤에도) | `/exam/lib/qna_badge.php` 를 브라우저로 열어 본다. **404 면 `lib` 폴더가 안 올라갔다** |
| 문제풀이 화면 넷째 탭이 빈 목록 | `api/board.php` 가 게시판을 못 읽는다. 화면이 이유를 말해 준다(`게시판 없음` vs `테이블을 읽지 못했습니다`) |
| `승인은 됐지만 게시판 댓글에 실패했습니다` | 원글이 삭제됐거나 게시판 테이블 구조가 다르다. 승인은 유효하니 게시판에서 직접 답글을 단다 |
| 초안이 일반론만 쓴다 | 문항이 연결되지 않았다. 질문 밑에 `m01-7#61` 이 없으면 그 상태다 |
| `Call to undefined function ex_llm_call` | `adm/exam_lib/llm.php` 가 안 올라갔다 |

## 상태가 뜻하는 것

```
pending → drafting → draft_ready → approved
   대기    초안 생성 중   검수 대기      완료
                                   └→ rejected  반려
```

| 표시 | 뜻 |
|---|---|
| <kbd>초안 있음</kbd> | `qa_draft` 가 있다. **이용자에게 안 보인다** |
| <kbd>차감 미확정</kbd> | 포인트는 빠졌는데 `qa_credit_ok = 0`. 원장은 맞지만 **수동 확인 대상** |
| <kbd>오류 신고</kbd> | `kind = report`. 무료이고 문항 수정으로 이어질 수 있다 |
| <kbd>비공개</kbd> | 답변이 질문자에게만 보인다 |

정렬은 **검수 대기가 맨 위, 그다음 오래된 질문 순**이다. 오래 기다린 사람이 먼저 답을
받아야 한다.
