## 0. FileZilla 접속

카페24 웹호스팅은 **FTP 계정 = 서비스 아이디**다.

| 항목 | 값 |
|---|---|
| 호스트 | `axexam.mycafe24.com` (또는 `112.175.85.162`) |
| 사용자 | `axexam` |
| 비밀번호 | 카페24 **FTP 비밀번호** (로그인 비번과 다를 수 있다) |
| 포트 | `21` (FTP) · SSH 되면 `22`(SFTP) 권장 |
| 프로토콜 | FTP → "명시적 FTP over TLS" 우선 |

비밀번호를 모르면: 카페24 로그인 → **나의서비스관리 → 웹호스팅 → 관리 → FTP 정보/비밀번호 변경**

### ⚠ 웹루트는 최상위가 아니라 `www/` **안**이다

`www` 는 **이미 서버에 있다. 만드는 게 아니라 들어가는 것이다.**
접속하면 이런 구조가 보인다:

```
/                     ← 여기가 아니다
├── www/              ← ★ 여기가 웹루트. axexam.mycafe24.com/ 이 이 폴더다
│   ├── common.php    ← 이게 보이면 제대로 온 것
│   ├── adm/  bbs/  lib/  data/  extend/  plugin/  shop/  skin/  theme/
│   ├── install/      ← ★ 지울 것
│   ├── probe.php     ← ★ 지울 것
│   └── version.php
├── logs/
└── (기타)
```

FileZilla 오른쪽 위 **`원격 사이트:` 칸이 `/www`** 이면 맞다.
최상위(`/`)에서 지우면 아무 일도 일어나지 않는다 — 지운 줄 알았는데 사이트는 그대로다.

### ⚠ 폴더는 파일보다 위에 있다

FileZilla 목록은 **디렉터리가 먼저, 파일이 나중**이다. 하단에 `24 파일 / 14 디렉터리` 라고 뜨는데
`probe.php` 같은 파일이 보이는 화면이면 `install/` 같은 폴더는 **스크롤 위쪽**에 있다.

### ⚠ "서버에 의해 연결 닫힘" 이면 삭제가 안 먹는다

FTP 는 유휴 시간이 길면 서버가 끊는다. 로그에 `서버와의 연결이 종료됨` 이 있으면
목록은 남아 있어도 **삭제·업로드가 실패한다.** 툴바 왼쪽 끝 아이콘이나 `빠른 연결` 로 다시 붙는다.

삭제 후에는 **반드시 브라우저로 404를 확인한다.** FileZilla 목록만 보고 판단하지 않는다.

## 1. 백업 — 최소 백업이면 충분하다

사이트가 오늘 자동설치된 **빈 그누보드**다. 콘텐츠가 없으므로 전체 다운로드(수만 개 파일, FTP로 20~30분)는
가치가 낮다. **정말 필요한 건 둘뿐이다.**

### (a) `www/data/` 폴더 — 필수

받는 법: FileZilla **왼쪽(로컬) 창**에서 `_backup` → `20260729` 로 들어간 뒤,
**오른쪽(원격)** 의 `data` 폴더를 왼쪽으로 끌어다 놓는다.
결과: `D:\00work\260729-new\_backup\20260729\data\`

`data/dbconfig.php` 에 **DB 접속정보**가 들어 있다. 이게 날아가면 사이트가 DB를 못 찾는다.
5.6.34 덮어쓰기에서 유일하게 보존해야 하는 폴더이기도 하다.

### (b) DB export — **지금은 건너뛴다**

지금 DB 에 든 건 오늘 자동설치된 **빈 그누보드**다(설정 테이블, 빈 게시판, 관리자 계정 1개).
그리고 **5.6.34 덮어쓰기는 파일만 건드리고 DB 를 건드리지 않는다.** `/adm/` 에서 스키마
업그레이드가 떠도 컬럼 추가라 파괴적이지 않다. 정작 중요한 `dbconfig.php` 는 (a) 에서 받았다.

DB 백업이 실제로 필요해지는 시점은 **S4 에서 문제 300건을 임포트한 뒤**다.

| 방법 | 쓸 수 있는 시점 |
|---|---|
| 카페24 `계정관리 → DATA&DB복원/백업` | ⚠ **오늘은 안 된다.** 새벽 5시 스냅샷 기준 1~7일 전 자료만 준다. 계정이 오늘 생겨서 스냅샷이 없다. **내일부터** 가능 |
| **phpMyAdmin** `https://mysql.cafe24.com/` | 지금도 가능. 계정 `axexam` + **DB 비밀번호**(`서비스 접속관리 → DB 비밀번호 변경`). 사이트 안(`/myadmin/` 등)에는 없다 — 카페24 중앙 서버다 |

받을 곳(나중에): `D:\00work\260729-new\_backup\YYYYMMDD\axexam-db-YYYYMMDD.sql`

### (c) 사이트 전체 — 선택

여유 있으면 `www/` 통째로 받아 `_backup\20260729\www\` 에 둔다.
없어도 그누보드는 GitHub 릴리스에서 다시 받으면 되므로 치명적이지 않다.

> `_backup/` 은 `.gitignore` 에 있어서 GitHub 로 올라가지 않는다. (확인됨)

## 2. `probe.php` 삭제

`www/probe.php` 를 지운다. (최상위 아님 — `www` 안)

**확인**: 브라우저에서 `https://axexam.mycafe24.com/probe.php` → **404 Not Found** 가 떠야 한다.

## 4. 그누보드 5.6.13 → 5.6.34 덮어쓰기

1. https://github.com/gnuboard/gnuboard5/releases 에서 **최신 정식 릴리스** 다운로드
   (`shop/` 이 설치돼 있으므로 영카트 포함 전체 패키지)
2. 로컬에 압축을 푼다
3. **압축 푼 폴더에서 `data/` 를 통째로 삭제한다** ← 이걸 먼저 지워야 실수가 안 난다
4. `install/` 도 삭제한다 (다시 올릴 이유가 없다)
5. 나머지 전부를 FTP로 `www/` 에 **덮어쓰기** 업로드
   - FileZilla 가 물어보면 **"덮어쓰기"** + "이 작업을 항상 사용"
6. `https://axexam.mycafe24.com/adm/` 접속 → DB 업그레이드 안내가 뜨면 따른다
7. `https://axexam.mycafe24.com/version.php` 또는 `/adm/` 하단에서 **5.6.34** 확인

**절대 덮어쓰면 안 되는 것**: `www/data/` (특히 `data/dbconfig.php`)

## 6. `probe_waf.php` — 이게 이번 단계의 핵심

`_probe/probe_waf.php` 를 `www/` 에 올리고 `https://axexam.mycafe24.com/probe_waf.php` 를 연다.

화면에 **[전송] 버튼 3개**가 있다. 각각 눌러서 새 탭 결과를 본다.

| 결과 | 뜻 |
|---|---|
| `POST 수신 OK` | 통과 |
| **406 / 403 / 빈 화면** | **WAF 가 죽였다** |

**왜 중요한가**: 우리 사이트는 학습자 질문 본문에 `SELECT ... WHERE 1=1` 같은 SQL 이 담긴다.
이게 막히면 **질문 등록 = 유료 기능 전체**가 성립하지 않는다.
어느 케이스가 막히느냐에 따라 대응이 달라서 판정 기준을 파일 안에 적어뒀다.

같은 화면 위쪽에 `upload_max_filesize` / `post_max_size` 도 찍힌다 —
`problems.json` (현재 387KB) 임포트가 되는지의 전제다. **이 숫자를 알려줄 것.**

### ⚠ 확인이 끝나면 `probe_waf.php` 를 반드시 삭제한다

서버 설정이 노출된다. `probe.php` 와 같은 이유다.

## 7. 카페24 콘솔 설정

`hosting.cafe24.com/?controller=myservice_hosting_main` → **호스팅관리 → 기본관리 → 서비스 사용현황**

| 설정 | 위치 | 할 일 |
|---|---|---|
| **하드 알림 수신** | 같은 페이지 `하드 알림 설정` → [설정하기] | **켜기** — 1,400MB |
| **트래픽 알림 수신** | 같은 페이지 `트래픽 알림 설정` → [설정하기] | **켜기** — 월 4,000MB. 마이캐쉬 0원 + 자동리셋 꺼짐이라 초과하면 사이트가 멈춘다 |
| 만료일 **2027-07-28** | — | 캘린더 등록 (자동연장 미사용이라 그냥 죽는다) |
| **DB 백업** | 왼쪽 `계정관리 → DATA&DB복원/백업` | phpMyAdmin 보다 이게 낫다 — 파일+DB 를 한 번에 받는다 |

휴대폰번호(관리자 정보)는 이미 등록돼 있으므로 **수신 여부만** 바꾸면 된다.

### ⚠ 보안관리 메뉴 — 나중에 막히면 여기부터 본다

왼쪽 `보안관리` 에 우리 기능을 오탐으로 죽일 수 있는 게 셋 있다. **지금은 건드리지 않는다.**
증상이 나타났을 때 순서대로 확인한다.

| 메뉴 | 증상 | 관련 |
|---|---|---|
| **웹방화벽(ModSecurity)** | 질문 등록 POST 가 406/403 | §6 `probe_waf.php` 로 먼저 테스트. **콘솔에서 직접 조작 가능하다** — 고객센터 요청이 필요 없다. 단 통과하면 건드리지 않는다(공격면만 넓어진다) |
| **업로드가드 설정** | `problems.json`(387KB) 업로드 실패 | S4 문제 임포트 |
| **PHP 안티웹셸 설정** | 올린 `api/*.php`·`adm/exam_*.php` 가 사라지거나 500 | S5~S8. PHP 파일을 웹셸로 오탐할 수 있다 |

`게시판 스팸필터관리` 도 질문 POST 를 막을 수 있다(HOSTING.md 참조).
