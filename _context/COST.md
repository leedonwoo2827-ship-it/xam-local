# 운영비·과금 설계

작성 2026-07-29. 대상 독자: 운영자(본인) + B2B 도입 검토자(wowpass, 유비원평생교육원 등).

이 문서는 **운영비 관점**의 계산이다. 고객 노출 문구와는 분리한다 — 내부 단위는 원(KRW), 고객에게는 "질문 N개"로 환산해 보여준다.

---

## 0. 확정된 정책

| 항목 | 값 |
|---|---|
| **크레딧 단위** | **원(KRW), 정수.** "건수"가 아니다 |
| **현 사이트 차감** | **질문 1건 = 10원** |
| 대상 자격증 (현 단계) | SQLD, ADSP, 정보처리기사 **필기**, 정보처리기사 **실기**, 컴활 — IT 자격증 계열 |
| 도메인 혼용 | **하지 않는다.** 대분류(자격증군)는 상위에서 분리하고, 한 사이트 안에서는 단일 토큰비 기준으로 운영 |
| 고객 노출 | 차감 단가는 **노출하지 않을 수 있다.** "질문 N개 남음"으로 환산 표시 |
| 부족 시 | 관리자가 추가 부여 (수동 유연성 유지) |

**크레딧 단위를 "원"으로 잡은 이유가 이 설계의 핵심이다.** 건수로 잡으면 도메인·모델이 바뀔 때마다 상품과 잔액의 의미가 흔들린다. 원으로 잡으면 차감 단가만 바꾸면 되고, 운영비 계산이 그대로 회계와 맞는다. 1,000원 충전 = `lot_qty 1000`, 질문 1건 = `cost 10` → 100건. 표시는 `floor(잔액 / 현재단가)`.

## 1. LLM 원가 — 실측 기준

### 단가표 (2026-07 확인)

| 티어 | 모델 | 입력 $/1M | 캐시읽기 $/1M | 출력 $/1M |
|---|---|---|---|---|
| T1 | DeepSeek V4-Flash | 0.14 | 0.0028 | 0.28 |
| T1 | 샤오미 MiMo-V2.5 | 0.14 | 0.0028 | 0.28 |
| T1 | Gemini 2.5 Flash-Lite | 0.10 | — | 0.40 |
| T2 | Claude Haiku 4.5 | 1.00 | 0.10 | 5.00 |
| T3 | Claude Sonnet 5 | 3.00 (프로모 2.00, ~2026-08-31) | 0.30 (0.20) | 15.00 (10.00) |
| T4 | Claude Opus 5 | 5.00 | 0.50 | 25.00 |
| T5 | Claude Fable 5 | 10.00 | 1.00 | 50.00 |

Anthropic 캐시 읽기는 입력가의 0.1배, 캐시 쓰기는 1.25배(5분 TTL) 또는 2배(1시간 TTL). DeepSeek 캐시 히트는 입력가의 0.02배.

### 건당 원가 (환율 1,400원)

가정: 입력 2,000토큰(시스템 규칙 + 문제 + 선택지 + 공식 해설) / 출력 1,000토큰

| 모델 | 캐시 미스 | 캐시 히트(1,800 캐시 + 200 신규) |
|---|---|---|
| **DeepSeek V4-Flash** | **0.78원** | **0.44원** |
| MiMo-V2.5 | 0.78원 | 0.44원 |
| Gemini 2.5 Flash-Lite | 0.84원 | — |
| Claude Haiku 4.5 | 9.8원 | 7.5원 |
| Claude Sonnet 5 (프로모) | 19.6원 | 15.0원 |
| Claude Sonnet 5 (정가) | 29.4원 | 22.9원 |
| Claude Opus 5 | 49원 | 37.7원 |
| Claude Fable 5 | 98원 | 75원 |

계산 예시 (DeepSeek 캐시 미스):
```
입력  2,000 × $0.14 / 1,000,000 = $0.00028
출력  1,000 × $0.28 / 1,000,000 = $0.00028
합계                              $0.00056 × 1,400 = 0.78원
```

### 긴 답변 시나리오 (원가 폭주 경로)

입력 3,000 / 출력 2,000 기준:

| 모델 | 건당 |
|---|---|
| DeepSeek V4-Flash | 1.37원 |
| Claude Haiku 4.5 | 18.2원 |

## 3. 진짜 원가 항목 — 우선순위 순

건당 10원 차감에서 실제로 손익을 결정하는 것들. **LLM은 4순위다.**

### 1순위 — 관리자 검수 노동 (압도적)

검수 1건 2분, 시급 20,000원 환산 시 **건당 667원.** LLM 원가의 850배다.

| 구독자 | 월 질문 (1인 12건) | 검수 시간 | 인건비 환산 | 월 매출(1,100원) |
|---|---|---|---|---|
| 10명 | 120건 | 4시간 | 80,000원 | 11,000원 |
| 50명 | 600건 | 20시간 | 400,000원 | 55,000원 |
| 100명 | 1,200건 | 40시간 | 800,000원 | 110,000원 |
| 500명 | 6,000건 | 200시간 | 4,000,000원 | 550,000원 |

**즉 검수를 인건비로 환산하면 어떤 규모에서도 적자다.** 1인 운영이라 인건비가 회계에 안 잡히는 것뿐이고, 실질은 시급 275원(100명 기준)이다.

→ **검수 효율화가 유일하게 의미 있는 원가 절감이다.** LLM 단가를 절반으로 줄여도 건당 0.4원이 절약되는데, 검수 시간을 2분에서 30초로 줄이면 건당 500원이 절약된다.

**검수 시간 단축 수단 (효과 순):**

| 수단 | 예상 효과 | 구현 위치 |
|---|---|---|
| 질문 전 기존 공개 답변 노출 + "이걸로 해결됐어요" | 중복 질문 30~60% 소멸 (질문권 차감 0) | 문제 카드 렌더 |
| 초안 그대로 승인 원클릭 + 키보드 단축키(Enter/J/R) | 1건 2분 → 30초 (4배) | 검수 화면 |
| `[검수필요]` 자진신고 초안만 정독, 나머지는 스캔 | 정독 대상 20~30%로 축소 | 프롬프트 규칙 2 |
| 같은 문제 반복 질문 묶어 표시 | 문맥 재파악 시간 절약 | 검수 화면 정렬 |

**자동 승인은 만들지 않는다.** 저가 모델은 SQL 실행 결과와 계산에서 조용히 틀린다. 검수를 건너뛰는 순간 신뢰가 무너지고, 그 회복 비용이 절약분을 압도한다.

### 2순위 — PG 고정비 (수수료가 아니다)

**정정 (2026-07-29):** 이 절은 처음에 "건당 고정 수수료 100원" 가정으로 썼는데 **틀렸다.** 토스페이먼츠 서비스 이용계약서 원문을 확인한 결과 **정기결제(빌링) 카드결제 행에는 건당 고정 수수료 컬럼이 존재하지 않는다.** 상세 근거는 [PAYMENT.md](PAYMENT.md) §4.

#### 수수료는 문제가 아니다

1,100원 = 공급가액 1,000 + 부가세 100 기준:

| 케이스 | 요율 | 수수료(VAT포함) | 실입금 | 실효율 |
|---|---|---|---|---|
| 토스 **일반/신규** | 3.40% | **41원** | 1,059원 | **3.74%** |
| 토스 **영세 우대**(계약서 기준, 연매출 3억↓) | 1.50% | **18원** | 1,082원 | **1.65%** |
| 스텝빌링 공시 하단 | 1.70% | 21원 | 1,079원 | 1.87% |
| ~~건당 100원이 있다면~~ (반증됨) | 3.4%+100 | 151원 | 949원 | 13.7% |

→ **3.74%든 1.65%든 1,100원 월정액은 수수료 측면에서 충분히 성립한다.**

⚠ 신규 사업자는 **처음에 일반요율(3.4%)** 이다. 여신금융협회가 매년 1·7월 재산정하고 영세 확인 시 차액을 소급 환급한다.

⚠ **카카오페이 "영세가맹점 수수료 무료"는 상시 제도가 아니다** — 2025년 명절 한시 이벤트(9/19~10/2 약 2주)였다. 온라인 정기결제 상시 면제는 어디에서도 확인되지 않는다. **이 정책을 손익 계산의 전제로 쓰면 안 된다.**

#### 진짜 문제는 초기 고정비다

| 항목 | 금액 |
|---|---|
| 가입비 (최초 1회) | 220,000원 |
| 연관리비 (연 1회) | 110,000원 |
| **1년차 합계** | **330,000원** (VAT 별도 → 363,000원) |

```
1,100원 결제 1건당 순마진 = 1,100 - 41(수수료) - 100(부가세 납부) = 959원
손익분기 = 363,000 / 959 ≒ 379건
        = 구독자 32명을 12개월 유지  (또는 구독자 379명 1개월)
```

간이과세자면 부가세 부담이 줄어 분기점이 내려간다(세율 기준 **확인 필요**).

→ **PG 도입 시점이 구독자 30명 이하라면 가입비를 회수하지 못한다.** 그때까지는 계좌이체 수동 승인으로 버티는 게 맞다. 이게 Phase 3을 뒤로 미루는 정량적 근거다.

이행보증보험도 계약 전 제출 필수이지만 **신용도 우수 시 면제 가능**하고, 소액 예상 결제금액이면 면제 가능성이 있다(**확인 필요**).

#### 선결제의 실제 이득 — 수수료 절감이 아니다

**정직하게: 순수 % 구조에서 선결제는 수수료를 1원도 줄이지 않는다.**

| 플랜 | 결제액 | 연 결제 건수 | 연 수수료(3.74%) |
|---|---|---|---|
| 월 1,100원 | 1,100 | 12건 | **493원** |
| 3개월 3,300원 | 3,300 | 4건 | **493원** |
| 12개월 13,200원 | 13,200 | 1건 | **493원** |

그래도 선결제를 권하는 이유는 넷이다:

1. **갱신 실패 이탈 지점이 연 12회 → 1~4회.** 1,100원 구독의 최대 손실 요인은 수수료가 아니라 카드 만료·한도 초과로 인한 갱신 실패다.
2. **현금 선확보로 33만원 고정비를 조기 상각.** 12개월 선결제 28명이면 1년차 고정비가 즉시 회수된다(13,200 × 28 = 369,600원).
3. **카드사·PG 심사에서 소액 다건 거래는 리스크 등급이 올라간다.** 건수를 줄이는 게 유리하다.
4. **건당 고정 수수료 리스크 헤지.** 계약서에 없다는 것은 확인했지만 요율은 상점관리자/별지에 기재되므로 계약 시점에 붙을 가능성이 0은 아니다. 붙는다면 연 1,813원 → 603원으로 67% 절감된다.

**권고 설계:** 월 1,100원은 진입용으로 유지하고 **3개월 3,000원 / 12개월 11,000원** 을 기본값으로 노출한다. 질문권은 **월 50개씩 분할 지급, 이월 없음** — 이게 회계상 선수금 이연에도 자연스럽고, 아래 에스크로 예외("일정기간에 걸쳐 분할되어 공급되는 재화등")에도 정확히 부합한다.

#### 에스크로는 면제 가능성이 높다

법제처 「찾기쉬운 생활법령정보」 기준 결제대금예치 의무의 **적용 제외**:

- 신용카드로 구매하는 거래
- 배송이 필요하지 않은 재화등(게임, 인터넷 학원 수강 등) / 정보통신망으로 전송되는 재화
- 10만원 미만 소액거래
- 일정기간에 걸쳐 분할되어 공급되는 재화등

→ 카드 정기결제 + 디지털 질문권 + 1,100원 + 월 분할 공급. **4개 예외에 전부 걸린다.** 다만 정부24 통신판매업 신고 실무에서 이용확인증을 요구하는 경우가 많으므로 **관할 시·군·구청에 예외 해당 여부를 확인**해야 한다.

통신판매업 신고 자체도 면제 기준이 있다: **직전년도 통신판매 거래횟수 50회 미만 또는 부가세법상 간이과세자** (공정위 고시).

### 3순위 — 인프라 고정비

| 항목 | 월 |
|---|---|
| 국내 리눅스 웹호스팅 (최소~중간 플랜) | 1,500 ~ 5,000원 |
| 도메인 (.kr 연 15,000~20,000원) | 약 1,400원 |
| 영상 호스팅 | **0원** (유튜브) |
| 폰트 CDN | 0원 (jsdelivr) |
| **합계** | **약 3,000 ~ 6,500원** |

영상 30개 411MB를 유튜브로 옮기면서 호스팅 요구가 **414MB → 약 600KB(폰트 CDN 적용 시)** 로 줄었다. 용량·트래픽이 플랜 선택 기준에서 사라졌고, **PHP/DB 버전과 outbound curl 허용 여부만이 기준**이 됐다.

손익분기: 고정비 5,000원 ÷ 건당 마진 9.2원 = **월 544건.** 구독자 45명(1인 12건) 수준.

### 4순위 — LLM API

월 300건이면 **234원.** 위 세 항목 대비 무시할 수준이다.

## 4. 프롬프트 캐싱 — 유일하게 의미 있는 LLM 최적화

캐시 히트가 입력가의 0.02배(DeepSeek) / 0.1배(Anthropic)다. 메시지 순서만 지키면 걸린다.

```
[① 시스템 규칙        ] ← 완전 고정. 모든 요청에서 히트
[② 문제 + 선택지 + 정답 + 공식 해설] ← 문제별 고정. 같은 문제 2번째 질문부터 히트
[③ 수강생이 고른 보기 + 질문        ] ← 가변
```

**효과**: 건당 0.78원 → 0.44원 (44% 절감). 절대액은 작지만 **T3/T4 티어로 올라갈 때 절대액이 커진다** (Opus 5: 49원 → 37.7원, 건당 11원 절감).

**커버율 추정**: 문제 300개 × 상위 질문 3~5개가 쌓이면 같은 문제 재질문 비율이 올라간다. 초기 캐시 히트율은 낮고, 질문이 누적되면서 상승한다.

**검증 방법**: `ex_qna.qa_tok_cache` 컬럼에 캐시 히트 토큰(`prompt_cache_hit_tokens`)을 기록하고 대시보드에서 월별 히트율을 본다. 0이 계속 나오면 프롬프트에 타임스탬프·UUID 같은 무효화 요인이 들어간 것이다.

## 5. 원가 감시 — 코드에 박아둘 것

모델을 잘못 바꿔 조용히 적자가 나는 것을 막는 장치들.

### 5-1. 건당 원가 상한

```php
// adm/lib/llm.php
define('EXAM_COST_CAP', 3.0);   // 원. 차감 단가 10원의 30%
```

응답의 `usage`로 원가를 계산해 `ex_qna.qa_cost`에 기록하고, 상한 초과 시 검수 화면에 경고를 띄운다. 티어별로 다르게 해야 하므로 `ex_product.cost_cap` 컬럼으로 승격한다 — T4(Opus 5, 49원)에서 3원 단일 상한이면 항상 경고가 뜬다.

### 5-2. 출력 토큰 상한

```php
'max_tokens' => 1200,
```

프롬프트의 "400자 이내" 규칙과 이중 방어. 원가 폭주 경로가 긴 출력뿐이므로 이게 실질적인 최후 방어선이다.

### 5-3. Rate limit

```php
ex_rate('qna', 20, 86400);   // 하루 20건
```

정상 학습자가 못 넘는 선이고, 크레딧을 가진 회원이 스크립트로 1,000건을 밀어 LLM 원가를 태우는 것을 막는다.

### 5-4. 월별 대시보드 (`adm/index.php`)

```sql
-- 이번 달 LLM 원가 vs 매출
SELECT
  (SELECT COALESCE(SUM(qa_cost),0) FROM ex_qna
    WHERE qa_draft_at >= DATE_FORMAT(NOW(),'%Y-%m-01'))            AS llm_cost,
  (SELECT COALESCE(SUM(od_price),0) FROM ex_order
    WHERE od_status='paid' AND paid_at >= DATE_FORMAT(NOW(),'%Y-%m-01')) AS revenue,
  (SELECT COUNT(*) FROM ex_qna WHERE qa_status='pending')           AS pending,
  (SELECT COALESCE(AVG(qa_cost),0) FROM ex_qna
    WHERE qa_draft_at >= DATE_FORMAT(NOW(),'%Y-%m-01'))             AS avg_cost,
  (SELECT COALESCE(SUM(qa_tok_cache)/NULLIF(SUM(qa_tok_in),0),0) FROM ex_qna
    WHERE qa_draft_at >= DATE_FORMAT(NOW(),'%Y-%m-01'))             AS cache_hit_rate;
```

**보아야 할 숫자 5개**: 이번 달 LLM 원가 / 매출 / 대기 질문 수 / 건당 평균 원가 / 캐시 히트율.

### 5-5. 크레딧 정합성

```sql
SELECT (SELECT COALESCE(SUM(lg_amt),0) FROM ex_credit_ledger) AS ledger_sum,
       (SELECT COALESCE(SUM(lot_qty - lot_used),0) FROM ex_credit_lot) AS lot_avail;
```

원장이 append-only라 언제든 대조 가능하다. 불일치가 나면 `lg_ref`로 추적한다.

## 6. 도메인 확장 시 — 사이트를 분리한다

**도메인을 섞지 않는다는 정책이 여기서 중요해진다.** 자격증군마다 요구 모델이 다르고, 같은 사이트에서 섞으면 크레딧 단가가 이용자에게 설명 불가능해진다.

| 자격증군 | 문제 유형 | 필요 티어 | 건당 원가 | 차감 단가(권고) | 1,000원 = |
|---|---|---|---|---|---|
| **SQLD / ADSP / 정보처리기사 필기 / 컴활 필기** | 객관식 4~5지선다 | T1 | 0.8원 | **10원** | 100건 |
| 정보처리기사 실기 | 단답·약술·SQL 작성 | T1~T2 | 0.8~10원 | 30원 | 33건 |
| 컴활 실기 | 엑셀/액세스 조작 절차 | T2 | 10원 | 30원 | 33건 |
| (먼 얘기) 수학·경제 | 다단 계산 추론 | T3 | 20원 | 60원 | 16건 |
| (먼 얘기) CFA 1/2 | 계산 + 개념 | T3 | 20원 | 60원 | 16건 |
| (먼 얘기) CFA 3 서술 / 논술 채점 | 루브릭 채점 | T4 | 40~90원 | 150원 | 6건 |

차감 단가를 원가의 3~15배로 잡는 근거는 **검수 노동이 원가의 대부분**이라는 것이다(§3). T1에서 12배 마진이 나는 건 검수 노동을 회계에 안 잡기 때문이고, T4에서 3배 마진이면 검수 노동을 감당할 수 없다.

**정보처리기사 실기·컴활 실기 주의**: 문제 형태가 객관식이 아니다. 실기는 "답안 작성" 또는 "조작 절차"이므로 (a) 정답 판정이 문자열 비교로 안 되고, (b) 부분점수 개념이 필요하고, (c) 프롬프트 재료에 채점 기준이 있어야 한다. **현 파이프라인(`02/`~`05/`)은 객관식 전용이므로 실기는 문제 데이터 제작부터 다시 해야 한다.** 티어 문제가 아니라 콘텐츠 문제다.

**논술·약술 채점은 별개 기능이다.** 질문 답변(질문 → 답변)과 답안 채점(답안 + 루브릭 → 점수 + 피드백)은 프롬프트도 검수 흐름도 다르다. `ex_qna.kind` 컬럼(`qna` / `grade`)으로 구분하고, **루브릭 작성이 선행 조건**이다. 루브릭 없이는 어느 모델을 써도 채점 일관성이 안 나오고, 그러면 관리자 검수가 사실상 재채점이 되어 건당 5분이 든다. 건당 40원 원가에 검수 5분이면 상품이 성립하지 않는다.

## 7. 스키마 반영

크레딧 단위가 "원"이고 차감량이 도메인별로 다르므로:

```sql
-- 차감 단가는 품목 설정값
ALTER TABLE ex_product ADD tier       VARCHAR(4)  NOT NULL DEFAULT 'T1';
ALTER TABLE ex_product ADD model_id   VARCHAR(48) NOT NULL DEFAULT 'deepseek-v4-flash';
ALTER TABLE ex_product ADD cost_units SMALLINT    NOT NULL DEFAULT 10;   -- 질문 1건당 차감(원)
ALTER TABLE ex_product ADD cost_cap   DECIMAL(8,4) NOT NULL DEFAULT 3.0; -- 원가 경고 상한(원)

-- 실제 차감량은 질문에 기록 (감사용. 단가가 바뀌어도 과거 기록이 보존됨)
ALTER TABLE ex_qna ADD cost_units SMALLINT NOT NULL DEFAULT 10;
```

`lot_qty`와 `lot_used`는 **원 단위**다. 1,000원 충전 = `lot_qty = 1000`.

차감 로직에서 `lot_used + 1` → `lot_used + :cost`로 바뀌지만 **조건부 UPDATE의 원자성은 그대로 유지된다**:

```sql
UPDATE ex_credit_lot
   SET lot_used = lot_used + :cost
 WHERE lot_id = :lot_id
   AND lot_used + :cost <= lot_qty
   AND lot_expire >= CURDATE();
-- affected_rows = 1 이면 성공, 0 이면 경쟁 패배 또는 잔액 부족
```

이 패턴은 그누보드 코어가 이미 검증한 것이다 — `insert_use_point()`의 주석: *"affected_rows로 성공/실패를 판별하고 실패 시 재시도하므로 락 없이 무결성 보장. (MyISAM/InnoDB 모두 호환, FOR UPDATE 불필요)"*. 자세한 근거는 [GNUBOARD-FACTS.md](GNUBOARD-FACTS.md) §5·§9.

**여러 lot에 걸치는 차감**: 잔액이 lot 하나로 부족할 때는 lot을 순회하며 부분 차감한다(FIFO, `ORDER BY lot_expire ASC, lot_id ASC`). 만료 임박분부터 쓰는 게 이용자에게 유리하다.

**환불은 `-cost`**. `ex_qna.cost_units`에 실제 차감액이 기록돼 있으므로 단가가 바뀐 뒤에도 정확히 되돌릴 수 있다. 이게 `cost_units`를 질문 행에도 저장하는 이유다.

**Phase 1에서 미리 넣어야 한다.** 나중에 넣으면 이미 발급된 lot의 의미(건수 vs 원)가 바뀌어 마이그레이션이 필요해진다.

## 8. 고객 노출 — 단가는 숨길 수 있다

내부 단위는 원이지만 화면에는 건수로 보여준다.

```
표시 건수 = floor(잔액 / 현재 차감단가)
```

| 화면 | 표시 |
|---|---|
| 헤더 | `질문 87개 남음` |
| 마이페이지 | `질문 87개 남음 · 8월 31일까지` |
| 구매 화면 | `월 1,100원 — 매월 질문 100개` |
| 원장 내역 | `7/29 질문 사용 · 잔여 87개` (원 단위 미표시) |

**단가를 노출하지 않는 이점**: 도메인·모델 변경 시 이용자에게 설명할 것이 없다. 단가를 올려도 "질문 개수가 줄었다"로만 보이므로 상품 재설계 없이 조정 가능하다.

**단가를 노출하는 이점**: "어려운 질문은 더 쓴다"가 직관적이라 T3/T4 도메인을 같은 사이트에 섞을 때 유리하다. 다만 **섞지 않기로 했으므로 지금은 불필요하다.**

→ **결론: 현 단계는 건수만 노출한다.** 원 단위는 관리자 화면에만 표시한다.

### 유효기간 고지는 반드시 명시적으로

미사용분 소멸이 실질 수익원이므로(사고 안 쓰는 이용자) **약관에 명확히 고지하고 구매 화면에서 별도 동의를 받는다.** 이건 법적 문제이기도 하고 윤리적 문제이기도 하다.

- 약관: 디지털 콘텐츠 청약철회 제한, 미사용분 환불 기준, **매월 소멸** 조항
- 구매 화면: "미사용 질문은 매월 소멸되며 다음 달로 이월되지 않습니다"에 체크박스 동의
- 동의 시각은 `ex_user_ext.agree_at`에 기록

## 9. 유연 운영 — 질문 많이 하는 회원

관리자가 크레딧을 수동 부여할 수 있게 둔다(`adm/exam_credit_grant.php`). 이유:

- 질문을 많이 하는 회원은 **가장 열심히 공부하는 회원**이고, 그 사람이 막히면 이탈한다. 건당 마진 9원을 아끼려고 이탈시킬 이유가 없다.
- 초기에는 표본이 작아 quota 수치의 적정선을 모른다. 수동 부여로 실사용 분포를 관찰한 뒤 정한다.
- B2B 도입 협의 시 "기관 계정에 일괄 부여" 같은 요구가 나올 수 있다. 수동 부여 경로가 있으면 개발 없이 대응된다.

`ex_credit_lot.lot_src = 'promo'` 또는 `'manual'`로 구분해 원장에 남긴다. 무료 부여분이 매출로 잡히지 않도록 `ex_order`와 분리한다.

## 10. B2B 도입 시 (wowpass, 유비원평생교육원 등)

현 설계가 B2B로 확장될 때 바뀌는 것과 안 바뀌는 것.

### 안 바뀌는 것 (설계상 이미 대응)

- **크레딧 원장** — 기관 계정에 대량 부여하고 소속 회원이 차감하는 구조로 확장 가능. `ex_entitlement`에 기관 ID를 추가하면 된다.
- **차감 단가 설정값** — 기관별 단가 협상이 `ex_product.cost_units` 또는 기관별 오버라이드로 처리된다.
- **원가 추적** — `ex_qna.qa_cost` 합계가 곧 기관별 원가 정산 근거다.
- **다품목** — `ex_product`에 행 추가. 질문권 공용이라 코드 변경 0.

### 새로 필요한 것

| 항목 | 규모 |
|---|---|
| 기관(조직) 개체 — 소속 회원 관리, 기관 관리자 권한 | 테이블 2개 + 화면 2개 |
| 기관별 사용량 리포트 (월별, 회원별, 자격증별) | 화면 1개 + 쿼리 |
| 기관 단위 정산 (선불 충전 또는 후불 청구) | `ex_order`에 기관 결제 유형 추가 |
| SSO / 기관 회원 일괄 등록 (CSV) | 화면 1개. OIDC는 이미 코어 지원 |
| 화이트라벨 (기관 로고·색상) | 테마 CSS 변수 오버라이드 |

**검수 노동이 B2B에서 병목이 된다** (§3). 기관 500명이면 월 6,000건, 검수 200시간이다. B2B 계약 전에 반드시 결정할 것:

1. **검수를 기관이 하는가, 우리가 하는가?** 기관 강사가 검수하면 노동이 이전되고, 우리가 하면 인건비를 계약가에 반영해야 한다.
2. **검수 SLA를 몇 시간으로 약속하는가?** "1일 이내"는 1인 운영으로 500명을 감당할 수 없다.
3. **자동 승인 티어를 도입하는가?** B2B 규모에서는 불가피해질 수 있다. 그 경우 `[검수필요]` 자진신고 초안만 사람이 보고 나머지는 자동 승인 + 사후 샘플 감사로 간다. 품질 리스크를 계약서에 명시해야 한다.

### 기관 제안용 원가 근거 요약

| 항목 | 건당 |
|---|---|
| LLM API (T1, IT 객관식) | 0.4 ~ 0.8원 |
| 인프라 (월 5,000원 ÷ 월 6,000건) | 0.8원 |
| **직접 원가 합계** | **약 1.6원** |
| 검수 노동 (2분 × 시급 20,000원) | 667원 |
| **검수 자동화 후 (30초)** | **167원** |

→ **기관 단가는 직접 원가가 아니라 검수 정책이 결정한다.** "건당 1.6원"으로 제안하면 검수 없는 서비스가 되고, "건당 170원"이면 검수 포함 서비스가 된다. 이 차이를 제안서에서 명확히 구분해야 한다.

## 12. 모델 검증 절차

"싸다고 좋은 게 아니다"를 실측으로 확인하는 절차. 결과는 `docs/model-eval.md`에 기록한다.

1. **표본 선정**: 자격증별 실제 문제 20~30건. 난이도 상/중/하 균등, 계산 문제와 개념 문제 균등.
2. **질문 유형 3가지**: (a) "왜 ③이 답인가", (b) "내가 고른 ①은 왜 틀렸나", (c) "이 개념을 더 설명해달라".
3. **후보 모델**: T1 3개(DeepSeek V4-Flash / MiMo-V2.5 / Gemini 2.5 Flash-Lite) 우선. T1이 부족한 자격증만 T2로 올린다.
4. **평가 항목**:
   - **사실 오류율** (가장 중요) — 공식 해설과 결론이 다른 비율
   - `[검수필요]` 자진신고 정확도 — 틀렸을 때 실제로 신고하는가
   - 검수 소요 시간 — 초안을 그대로 승인할 수 있는 비율
   - 건당 실측 원가 (`usage` 기록)
   - 한국어 자연성
5. **판정 기준**: **검수 시간이 원가 차이를 압도한다.** T1이 오류율 20%고 T2가 5%면, 건당 9원 더 내고 T2를 쓰는 게 총비용에서 유리하다 (검수 시간 절약이 건당 수백 원).

특히 **수학·계산 문제는 저가 모델이 산술과 다단 추론에서 조용히 틀린다.** 조용히 틀리는 게 문제다 — 검수자가 매번 계산을 재검증해야 하면 검수 시간이 몇 배로 늘어난다. 정보처리기사 실기의 SQL 작성, 컴활 실기의 함수 계산이 여기 해당할 가능성이 높다.

## 부록 A. 원가 계산기

```
건당원가(원) = (입력토큰 × 입력단가 + 캐시토큰 × 캐시단가 + 출력토큰 × 출력단가) / 1,000,000 × 환율

월 LLM비 = 건당원가 × 월 질문수
월 마진  = (차감단가 - 건당원가) × 월 질문수 - 고정비 - PG수수료
손익분기 = (고정비 + PG수수료) / (차감단가 - 건당원가)
```

현 설정 대입 (DeepSeek V4-Flash, 차감 10원, 고정비 5,000원, PG 무시):
```
손익분기 = 5,000 / (10 - 0.78) = 542건/월
```
