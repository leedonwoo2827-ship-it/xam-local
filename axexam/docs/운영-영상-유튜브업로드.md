# 운영 — 해설영상 유튜브 업로드

대상: 운영자 / 관리자
목적: 원고 검토 중인 영상을 안전하게 올리고, 확정되면 공개로 넘기는 절차

---

## 원칙 셋

1. **미등록(Unlisted)으로 올린다. 비공개(Private)가 아니다.**
   비공개는 초대한 구글 계정만 볼 수 있고 **embed 가 남에게 안 열린다.**
   미등록은 링크를 아는 사람만 보고 검색·추천·채널목록에 안 뜨는데 **embed 는 정상**이다.

2. **한 번 올린 영상은 내리지 않는다.**
   지웠다 다시 올리면 **영상 ID 가 바뀐다.** 그러면 `youtube_map.json` 을 다시 고쳐야 한다.
   검토가 끝나도 미등록 그대로 두고, 오픈 시점에 **공개로 전환만** 한다.

3. **영상 파일은 교체할 수 없다.** (유튜브 정책)
   제목·설명·썸네일·자막·공개범위는 바꿀 수 있지만 파일 자체는 못 바꾼다.
   내용을 고치려면 새로 올려야 하고 ID 가 바뀐다.
   앞뒤를 조금 자르는 정도는 **YouTube 스튜디오 → 편집기 → 자르기** 로 되고, 이건 ID 가 유지된다.

## 업로드 절차

1. **studio.youtube.com** → 우상단 **만들기 → 동영상 업로드**
2. mp4 선택 → 제목 입력
   - 원본 위치: `D:\00work\ocr-output-260723\05\<번들>\draft\<번들>.static.mp4`
   - 제목 예: `SQLD 자사 모의고사 1회 1~10번 해설`
3. **"아동용 아님"** 선택 ← 필수. 안 고르면 다음으로 안 넘어간다
4. 다음 3번 → **공개 상태** 단계에서 **"미등록"** 선택 → **저장**

## 영상 ID 확인

업로드가 끝나면 URL 이 나온다. **마지막 11자**가 ID 다.

```
https://youtu.be/dQw4w9WgXcQ
https://www.youtube.com/watch?v=dQw4w9WgXcQ
                                └─ dQw4w9WgXcQ  ← 이것
```

Studio → 콘텐츠 목록에서 영상에 마우스를 올리면 **링크 복사**가 뜬다.

## 매핑 파일에 기록

`D:\00work\260729-new\data\youtube_map.json`

```json
"m01-1": { "id": "dQw4w9WgXcQ", "label": "1회 1~10번", "sec": 0 },
"m01-2": { "id": "",            "label": "1회 11~20번", "sec": 0 },
```

- `id` 가 **빈 항목은 빌드가 건너뛴다** → 회차 단위로 하나씩 채워 나가면 된다
- `sec` 는 시작 지점(초). 0 이면 처음부터
- 이 파일은 **수동 관리 파일이고 빌드가 절대 덮어쓰지 않는다**

### 번들 ↔ 회차 대응

| 번들 | 범위 |
|---|---|
| `m01-1` `m01-2` `m01-3` `m01-4` `m01-5` | 1회 1~10 / 11~20 / 21~30 / 31~40 / 41~50번 |
| `m02-1` … `m02-5` | 2회 |
| … | |
| `m06-1` … `m06-5` | 6회 |

총 30편.

## 이론 강의 영상 — **문항 영상과 다른 칸이다**

요약노트(이론 탭)에 붙는 **과목별 강의**는 회차 영상과 섞이지 않는다. 같은 파일 안에서
칸이 갈리고, **키가 다르다** — 회차는 번들코드(`m01-1`), 이론은 **과목 번호**다.

```json
{ "_provider": "drive",
  "theory": { "1": { "id": "<공유 URL 또는 ID>", "label": "1과목 · 빅데이터 분석 기획 강의" },
              "2": { "id": "" } },
  "videos": { "m01-1": { "id": "…", "label": "1회 1~10번", "sec": 0, "min_level": 5 } } }
```

과목 번호는 `03/summary_*.html` 의 `<h1>N과목 · 이름</h1>` 에서 읽는다. 파일 이름이 아니라
`<h1>` 이 기준이다 — 렌더 mp4 이름(`1summary-planning.mp4`)의 앞자리는 참고일 뿐이다.

- `id` 가 빈 과목은 **버튼을 아예 그리지 않는다.** 죽은 버튼을 만들지 않는다
- `sec`(시작 초)는 쓰지 않는다. 강의는 처음부터 본다
- **`min_level` 이 없다.** 이론 링크는 공개 `theory.js` 에 실려 누구나 내려받는다.
  회차 영상처럼 레벨로 가리는 통로(`api/videos.php`)가 이론 탭에는 없다.
  가려야 한다면 `videos.private.json` 방식을 이론에도 옮기는 작업이 먼저다

### 넣는 법 — 앱에서 한 번에

앱 `#/publish` → 「② 영상 매핑 → 링크 붙여넣기」에 **렌더 파일명과 링크를 같은 줄에** 둔다.
과목 표기는 파일명·`2과목`·`t3` 아무 것이나 통한다(회차 줄과 섞어 붙여도 각자 자기 칸으로 간다).

```
1summary-planning.mp4   https://drive.google.com/file/d/1AbC…/view?usp=drive_link
2과목                    https://drive.google.com/file/d/2DeF…/view
```

카드 위쪽 배지에 `이론 4 / 4` 로 찍힌다. 「빠진 번들 채우기」를 눌러도 **이미 넣은 id 는
지워지지 않는다** — 과목이 늘면 빈 칸만 생긴다.

### 반영

빌드 → **`pd/<품목>/theory.js`** 한 파일. 요약노트 본문을 안 고쳤으면 `theory_content.js` 는
그대로다.

★ 버튼을 그리는 코드는 `exam/assets/check.js` 다. **이 파일이 서버에 옛것이면 링크를 넣어도
버튼이 안 뜬다.** 이론 영상을 처음 붙이는 서버라면 `check.js` 를 함께 올린다.

## 반영

```bash
python scripts/build_check.py --api-base ./api/
```

리포트에 `영상 5개 매핑 (5/30 유튜브 ID 입력됨)` 처럼 찍힌다.
그다음 **`06/videos.js` 만** FTP 로 `/www/exam/` 에 올린다. 다른 파일은 안 바뀐다.

사이트에서 확인: 홈 화면의 해당 회차 카드에 영상 버튼이 뜨고, 누르면 모달에서 재생된다.
ID 를 안 넣은 회차는 "영상 준비 중"으로 남는다.

## 검토에서 반려됐을 때

1. 로컬에서 mp4 다시 렌더
2. 유튜브에 **새로** 올린다 (미등록)
3. `youtube_map.json` 에서 그 줄의 `id` 만 새 값으로 교체
4. 빌드 → `videos.js` 업로드
5. **반려된 옛 영상은 유튜브에서 삭제한다** — 안 지우면 나중에 어느 게 확정본인지 모른다

약 2분 걸린다.

## 오픈 시점 — 공개 전환

Studio → 콘텐츠 → 영상 여러 개 선택 → **일괄 작업 → 공개 상태 → 공개**

**`youtube_map.json` 도 사이트 파일도 건드릴 필요가 없다.** 영상 ID 가 그대로이기 때문이다.

회차별 재생목록 6개를 만들어 두면 유튜브 쪽 유입에 도움이 된다(사이트 동작과는 무관).

## 왜 서버에 직접 올리지 않는가

| | 유튜브 미등록 | 서버 직접 호스팅 |
|---|---|---|
| 트래픽 | **0** | 1회차 완주 1인 = 78.4MB |
| 월 한도 4,000MB | 무관 | **51명이면 소진** (30편 전부면 9.7명) |
| 하드 1,400MB | 무관 | 411MB 점유 |
| 확정 후 작업 | 공개 전환 클릭 | 유튜브 재업로드 + 설정 수정 + 서버 파일 삭제 |

트래픽을 초과하면 **마이캐쉬 잔액이 0원이고 자동 리셋도 꺼져 있어 사이트가 멈춘다.**

> 그래도 서버 재생이 필요하면 `youtube_map.json` 항목에
> `"provider": "file", "id": "videos/m01-1.static.mp4"` 를 넣고 mp4 를 `/www/exam/videos/` 에 올리면 된다.
> 화면 코드는 `{provider, id}` 추상화라 수정이 필요 없다.
