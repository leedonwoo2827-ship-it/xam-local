## 1. 문제 임포트 · 수정 반영

### 1-1. 빌드

```
python scripts/build_check.py --api-base ./api/ --pd sqld --pd-name "SQL 개발자(SQLD)" --emit-json --prune
```

리포트에서 **과목 수**를 먼저 본다. SQLD 는 2종이어야 한다.
1종으로 나오면 `02/` 메타 조인이 깨진 것이고, 그대로 임포트하면 `sj_name` 이 300건 전부
`"SQLD"` 로 들어가 재임포트해야 한다.

### 1-2. 임포트

```
화면:  /adm/exam_import.php
파일:  D:\00work\ocr-output-260723\06\pd\<품목>\problems.json
```

기대값 — 내용을 안 고쳤다면:
```
신규 0 · 갱신 0 · 변경없음 300 · 건너뜀 0 · 실패 0 · 회차 6행
```

문제를 고쳤으면 **갱신**이 그 개수만큼 나온다. `pr_hash` 가 달라진 것만 UPDATE 된다.

### 1-3. 정적 데이터 업로드

```
06\pd\<품목>\theory.js · theory_content.js · videos.js · figs\ · theory\
   →  /www/exam/pd/<품목>/
```

`problems.js` · `problems.json` 은 **올리지 않는다.** 서버에서는 `api/problems.php` 가 이기고,
정답이 박힌 파일을 공개로 둘 이유가 없다.

> ⚠ **이론은 DB 가 아니다.** `theory_content.js` 에 구워져 있다. 이론을 고쳤으면 이 파일을 올려야 한다.
> 문제만 임포트하고 끝내면 이론은 안 바뀐다.

### 1-4. 확인

```
/adm/exam_import.php               결과 표
/exam/check.php?pd=<품목>&m=quiz   문제 수 · 도식(SVG)
/exam/check.php?pd=<품목>&m=theory 요약노트
```

문제를 고쳤으면 **새로고침만으로 반영된다** — 화면이 `api/problems.php` 를 실시간으로 읽는다.

## 3. 해설영상 링크 걸기

영상은 서버에 올리지 않는다. mp4 30개가 411MB 이고 월 트래픽이 4,000MB 다.
자세한 배경은 [운영-영상-유튜브업로드.md](운영-영상-유튜브업로드.md).

### 3-1. 어디에 올릴지 정한다

| 단계 | provider | 어디에 | 화면 동작 |
|---|---|---|---|
| **저자 검토** | `link` | 네이버 마이박스 · 구글 드라이브 · 드롭박스 — 아무 곳 | **새 창으로 링크만 열림.** 내려받아 각자 PC 에서 본다 |
| 완성품 | `youtube` | 유튜브 미등록(unlisted) | 화면 안에서 재생 |
| (참고) | `drive` | 구글 드라이브 | 화면 안에서 재생. 조회 쿼터가 있어 검토용만 |

검토 단계에 `link` 를 권한다 — embed API·조회 쿼터·공유 정책을 신경 쓸 필요가 없어 가장 튼튼하다.

### 3-2. 매핑 파일에 적는다

`data\youtube_map.json`

```json
"_provider": "link",     ← 검토 단계. 완성되면 youtube
"_min_level": 5,         ← 이 레벨 이상만 링크를 받는다. 완성되면 0

"videos": {
  "m01-1": { "id": "https://mybox.naver.com/share/list/AbCdEf", "label": "1회 1~10번" },
  "m01-2": { "id": "https://youtu.be/dQw4w9WgXcQ", "label": "1회 11~20번",
             "provider": "youtube", "min_level": 0 },
  ...
}
```

- **공유 URL 을 그대로 붙여넣는다.** ID 추출은 빌드가 한다(`build_check.py` 의 `video_id()`).
  드라이브 `/file/d/<id>` · `youtu.be/<id>` · `watch?v=<id>` · `vimeo.com/<id>` 를 알아본다.
- 항목별 `provider`·`min_level` 이 전역값을 이긴다 → **회차별로 하나씩 완성품으로 넘길 수 있다.**
- `id` 가 빈 항목은 빌드가 건너뛴다. 죽은 버튼이 안 생긴다.

### 3-3. 빌드하고 두 파일만 올린다

```
python scripts/build_check.py --api-base ./api/ --pd sqld --pd-name "SQL 개발자(SQLD)"

06\pd\sqld\videos.js              →  /www/exam/pd/sqld/videos.js
06\pd\sqld\videos.private.json    →  /www/exam/pd/sqld/videos.private.json
```

수 KB 다. 다른 건 올릴 필요 없다.

### 3-4. 검토자 레벨을 올린다

```
/adm/member_list.php  →  회원 클릭  →  권한 레벨 5 이상
```

그누보드 레벨: 1 비회원 · 2 일반회원 · … · 10 최고관리자.

### 3-5. 왜 레벨 게이트가 서버에서 도는가

`videos.js` 는 정적 파일이라 **주소만 알면 누구나 내려받는다.** 화면에서 버튼만 숨겨도
링크는 파일 안에 그대로 남는다 — 가리는 척일 뿐이다.

그래서 `min_level` 이 2 이상인 항목은 `videos.js` 에 **아예 넣지 않고** `videos.private.json` 으로
빼고, `api/videos.php` 가 로그인 레벨을 보고 내려준다. 레벨이 안 되면 링크가 브라우저에 도달하지 않는다.
(`videos.private.json` 은 `.json` 이라 `/exam/.htaccess` 가 직접 조회를 막는다. 서버는
파일시스템으로 읽으므로 무관하다.)

> ⚠ **외부 공유 링크는 그 자체가 접근 권한이다.** URL 을 아는 사람은 레벨과 무관하게 본다.
> 레벨 게이트는 "URL 을 아는 사람을 줄이는 것"이고 마이박스·드라이브의 공유 설정을 대신하지 못한다.
> **검토가 끝나면 그쪽 공유를 끊는다.**

### 3-6. 완성품으로 전환

```
1. youtube_map.json:  "_provider": "youtube"  ·  "_min_level": 0
2. 각 id 를 유튜브 URL 로 교체
3. 재빌드
4. pd/<품목>/videos.js 만 다시 올림
```

유튜브는 **미등록으로 올리고 확정되면 공개로 전환만** 한다. 영상 ID 가 그대로라 매핑 파일을
다시 안 고친다. ⚠ 지웠다 다시 올리면 ID 가 바뀐다 — 내리지 않는다.

## 4. 수강 신청 승인

```
화면:  /adm/exam_orders.php
```

`대기` 탭에서 **[승인]**. 승인이 하는 일:

```
1. od_status : pending → paid       (조건부 UPDATE — 동시 클릭 중 하나만 통과)
2. ex_entitlement upsert            (월 지급의 원천. 연장이면 months_paid 를 더한다)
3. 첫 달 + 밀린 달 포인트 지급       (만료 = 지급일 + 1개월 − 1일)
```

**멱등이다.** 원장 키가 `drip:<품목>:<YYYY-MM>` 이고 `uq_month` 제약이 겹쳐 있어
버튼을 두 번 눌러도 포인트가 두 번 들어가지 않는다.

**포인트는 문제집별이다.** SQLD 를 승인해도 다른 문제집 잔액은 늘지 않는다.

> ⚠ **취소는 이미 지급된 포인트를 회수하지 않는다.** 회수가 필요하면 절차 5 에서 음수로 조정한다 —
> 원장에 흔적이 남아야 나중에 설명할 수 있다.
>
> ⚠ **결제는 받지 않는다.** `od_method='manual'` 이고 입금 확인은 화면 밖에서 한다.

화면 상단의 **포인트 정합성**이 `일치` 인지 가끔 본다. `원장 합계 − 미기록 만료 = 유효 잔액`
이면 정상이다. 불일치가 나면 `lg_ref` 로 추적한다.

## 5. 포인트 지급 · 회수

```
화면:  /adm/exam_credit_grant.php
```

회원 아이디로 조회하면 **잔액 · 구독권 · 포인트 묶음 · 원장**이 다 나온다.

```
지급:  수량 1000  (1,000원 = 질문 100개. 단가 10원)
회수:  수량 -500  (음수)
사유:  필수. 원장에 남아 나중에 설명할 근거가 된다
```

- **같은 회원에게 몇 번이든 지급된다** — 강제 지급은 `lot_period = NULL` 이라 유니크 키에 걸리지 않는다.
- **회수는 남은 잔액에서만 된다.** 이미 쓴 분은 회수되지 않는다 — 잔액이 음수가 되는 상태를 만들지 않는다.
- 조회할 때마다 **월 지급 정산이 먼저 돈다**(cron 이 없어 조회 시점에 정산한다).

화면에 원 단위가 보이지만 **이용자 화면에는 개수만 보인다**(`floor(잔액 / 단가)`).

## 6. 질문 검수 · 답변

```
목록:  /adm/exam_qna_list.php     기본 탭이 '미처리'
답변:  목록에서 클릭
```

정렬은 **검수 대기가 맨 위, 그 다음 오래된 질문 순**이다. 오래 기다린 사람이 먼저 받는다.

답변 화면은 왼쪽에 문제(정답·해설 포함), 오른쪽에 질문·답변란이다.

```
저장만       qa_answer 만 저장. 상태 안 바뀜 (다듬는 중)
승인 · 공개  approved → 이용자에게 공개된다
반려 · 환불  rejected + 포인트 환불 + qa_refunded=1
```

- **해설이 이미 답을 담고 있으면 해설을 인용해 끝낸다.** 새로 쓰면 나중에 어긋난다.
  해설 자체가 부족하면 `02/` 원본을 고치는 것이 근본 해결이다.
- **공개** 체크를 켜두면 과목게시판·문제 카드에 쌓여 다음 사람의 중복 질문을 막는다.
  개인 사정이 섞인 질문만 비공개로.
- `차감 미확정`(빨강)은 포인트는 빠졌는데 `qa_credit_ok=0` 인 경우다. 원장에는 차감이 남아
  회계는 맞지만 **수동 확인 대상**이다.
- `초안 있음`(파랑)은 LLM 초안이 있다는 뜻이다. **이용자에게는 절대 보이지 않는다** —
  회원 API 의 SELECT 목록에 그 컬럼이 없다. 승인해서 `qa_answer` 로 확정한 것만 공개된다.

**반려하면 환불한다.** 답을 못 하는데 포인트를 가져가면 민원이 된다.

```
화면:  /adm/exam_board_sync.php  →  [말머리 맞추기]
```

`ex_problem` 의 과목명을 `sj_no` 순서로 뽑아 게시판 말머리(`bo_category_list`)에 넣고
`기타`를 붙인다.

**언제 다시 누르나** — 문제를 재임포트해서 과목이 바뀌었을 때. 상태가 `말머리 불일치` 로 뜬다.

> ⚠ **말머리를 손으로 고치지 않는다.** 과목명과 한 글자라도 다르면 그 과목 필터가 빈 목록이 되고
> **에러는 나지 않는다.** 사람이 잡기 가장 어려운 종류의 고장이라 자동화했다.
>
> `기타`를 붙이는 이유 — 과목이 애매한 질문(접수·학습법)이 반드시 들어온다. 받을 말머리가 없으면
> 이용자가 아무 과목이나 골라서 과목 필터의 신뢰도가 떨어진다.

## 8. 브랜드 · 형제 사이트 만들기

어학XAMpass·금융XAMpass 는 **이 사이트를 복사해서** 만든다.
복사 후 고치는 것은 **둘뿐이고 코드 수정은 0** 이어야 한다.

```
① data\brand.json      브랜드 문자열
② ex_product 행        그 분야의 자격증들
```

`data\brand.json`
```json
{
  "brand": "어학XAMpass",
  "brand_html": "어학<i>XAM</i>pass",
  "tagline": "어학 자격증 문제은행",
  "intro": "자격증 문제은행과 1:1 질문 서비스. 문제·정답·해설을 전면 공개합니다."
}
```

빌드하면 `{{BRAND}}`·`{{BRAND_HTML}}`·`{{TAGLINE}}` 이 치환되고 `06\brand.php` 가 생성된다.
PHP 화면(`theme/axexam/head.php`·`tail.php`)은 그 파일을 include 한다.

`brand_html` 의 `<i>` 안쪽에 포인트색(노랑)이 칠해진다.

> 치환 안 된 토큰이 남으면 **빌드가 죽는다.** `{{BRND}}` 같은 오타가 배포되는 것을 막는 장치다.

## 9. 배포(업로드) 규칙

### 순서

```
1. DB 마이그레이션 (있으면)
2. 코드 (web\ → /www)
3. 빌드 산출물 (06\ → /www/exam)
4. 서버에서 지울 것
5. 관리자 작업
```

코드가 새 컬럼을 쓰므로 **DB 가 먼저**다.

### 관리자 화면은 메뉴 파일을 맨 마지막에

`adm/admin.menu600.exam.php` 는 **모든 관리자 페이지가 include** 한다. 문법 오류가 있으면
관리자 전체가 죽는다. 새 관리자 화면을 올렸으면 **주소로 직접 열어 확인한 뒤** 메뉴를 올린다.
(최고관리자는 메뉴 등록 없이도 통과한다.)

### assets 폴더는 폴더째 지우지 않는다

`/www/exam/assets/` 에는 빌드에 없는 파일이 함께 있다 —
`gnuboard-skin.css` · `mypage.css` · `mypage.js` · `check.css` · `check.js`.
폴더를 지우고 올리면 그것들이 사라진다. **파일만 덮어쓴다.**

### 크기로 비교하지 않는다

- **PHP** 는 응답만 나오고 소스가 안 나온다. 동작으로 확인한다.
- **정적 파일**도 FileZilla 가 CRLF→LF 로 바꿔 올려 줄 수만큼 작아진다. 정상이다.

### 검증 도구 (업로드 전에 돌린다)

```
python scripts/lint_php.py        문법 오류 — 백지 사고의 1원인
python scripts/check_columns.py   스키마에 없는 컬럼 참조
```

저장소에 그누보드 코어가 없어 로컬에서 화면을 띄울 수 없다. 이 둘이 그 공백을 메운다.

## 10. 사고 대응

| 증상 | 대처 |
|---|---|
| **사이트 전체 백지** | `/adm/` 은 살아 있다 → 환경설정에서 테마를 `basic` 으로. 또는 FTP 로 `/theme/axexam` 폴더명 변경 |
| **관리자 전체 백지** | `adm/admin.menu600.exam.php` 를 지운다. 메뉴만 사라지고 나머지는 돈다 |
| 특정 페이지만 백지·500 | 그 PHP 파일만 지운다. 나머지는 계속 돈다 |
| `check.php` 가 목록으로 튕긴다 | 그 품목에 문제가 0건이다. 임포트를 확인한다 |
| 도식이 안 보인다 | `pd/<품목>/figs/` 가 안 올라갔다 |
| 이론이 "찾을 수 없습니다" | `pd/<품목>/theory_content.js` 가 안 올라갔다 |
| 과목게시판이 "게시판이 만들어지지 않았습니다" | 절차 2-3 을 안 했다 |
| **포인트가 한 문제집만 들어온다** | `uq_month` 가 4컬럼인지 확인한다. 3컬럼이면 마이그레이션이 안 됐다 |
| 관리자 좌측 2차 메뉴가 안 보인다 | `extend/10_exam.php` 가 옛 버전이다(프론트 CSS 가 `/adm/` 에 새고 있다) |
| 주소창에 도메인만 쳤는데 엉뚱한 데로 감 | 브라우저가 캐시한 옛 301. 시크릿 창으로 확인 |

### 트래픽 한도

월 **4,000MB** · 마이캐쉬 0원 · 자동리셋 꺼짐. **초과하면 사이트가 멈춘다.**
카페24 콘솔 → 서비스 사용현황 → 트래픽 알림 · 하드 알림을 **수신**으로 켜둔다.

디스크는 1,400MB 다. `06\videos\` 의 mp4(411MB)를 올리면 안 된다 —
`build_check.py --prune` 이 지운다.
